## 1. 誰の、どの瞬間の困りごとか

findings §4-2 が挙げる5つの未充足ニーズのうち、①「勝者は分かったが信じていいのか分からない」②「どの基準が支配しているかが製品化されていない」④「結論ありきの重み逆算を誰も止めない」が、個人利用者の具体的な詰まりに直結する。以下の3場面はそこから構成した。

### 場面A — 転職オファー2社を今夜中に決める(締切のある個人決断)

findings §3-4(c) が記録している yesnowheelapp の実例そのものの状況。給与・通勤・成長・待遇を並べて採点し、7.4 対 7.1 で Job B が勝つ。

**既存ツールを使うと何が起きて詰むのか。** geratools / altftool / chamsdel / onlinetoolhubs / Argumentree(findings §1-B)はいずれも加重和と順位を出して終わる。この人が画面から受け取るのは「B が 7.4 で勝ち」という一行だけで、0.3 点差が何に由来するのかは分からない。findings §4-2-1 が引く通り「重みは測定値ではなく意見」であり、通勤の重みを 10% にしたのは今朝の気分でしかない。そこで人は必ず重みに戻ってスライダーを触り、A が勝つ配置を見つけ、また戻す —— これが findings §4-2-4 の motivated reasoning そのもので、どのツールも検知しない。chamsdel の「5点差以内なら僅差」ヒューリスティックは findings §1-B が「経験則で理論的裏付けなし」と明記しており、この 0.3 点差が僅差なのかどうかすら答えない。結果として、数字を出したのに決断の確信度はツールを開く前と変わらず、締切だけが迫る。

### 場面B — 3社のベンダー/SaaS を選び、社内に説明責任を負う(小チームの調達判断)

基準は価格・機能充足度・サポート・移行コストの4〜5個、選択肢は3社。決めた後に「なぜそれを選んだのか」を上長に説明する必要がある。

**既存ツールを使うと何が起きて詰むのか。** この用途を正面から扱う製品は findings §1-A の TransparentChoice(Software Advice 掲載で £4,000/年〜)と 1000minds($25,000/年、無料枠なし・必ず onboarding call)であり、findings §4-2-5 の通り TransparentChoice は公式FAQで「加重モデルは数学的厳密性と整合性チェックを欠く」と述べ、厳密性は有料層の対価だという立場を明示している。個人・小チームの予算では手が届かず、商談を経る時間もない。ではと ClickUp / Notion のテンプレート(findings §1-C)に降りると、重みも合計も手動運用の実質スプレッドシートで、Notion の一部テンプレートに至っては「Weight=100% にすればスコアだけで使える」という逃げ道が用意されている —— findings §1-C が指摘する通り、重みが正しく使われていない実態の裏返しである。そして最大の詰みは説明責任側にある。上長の質問は必ず「価格の重みをもう少し高く見ていたら結論は変わったのか」であり、findings §4-1 の表が示す通り、この問いに答えられる感度分析は無料Web層に**ほぼ全て無し**で、答えるには $12,000〜25,000/年 の層に上がるしかない。

### 場面C — 引っ越し先/進学先など、基準の重みに自信が持てない一回きりの人生判断

選択肢3〜4件、基準は家賃・通勤時間・環境・広さなど5個前後。当人は「何を重視すべきか」自体を決めかねている。

**既存ツールを使うと何が起きて詰むのか。** ここで人が本当に知りたいのは順位ではなく、findings §4-2-2 が「学術的には解けているのに製品化されていない」と指摘する問い —— どの基準が結論を握っているのか、である。Triantaphyllou & Sánchez (1997)(findings §3-4(a))は「最も重みの大きい基準が最も重大とは限らず、最も重みの小さい基準が最も重大でありうる」ことを示しているが、この計算をブラウザで無料で回せる製品は findings の調査範囲に存在しない。実装している SpiceLogic は findings §1-A の通り Windows デスクトップアプリでオフライン前提・共有不可・UIが学術ツール寄りであり、この人には届かない。加えて MyMap(findings §1-B)のように AI に感度分析を自然言語で依頼させる実装は「決定論的な数値手法として実装されておらず再現性・監査可能性が保証されない」ため、人生判断の根拠には使えない。結局この人は、重みをいじっては順位が入れ替わるのを眺め、どの配置が正しいのか分からないまま画面を閉じる。findings §4-2-3 の通り無料ツールは保存もできないので、翌週にはゼロからやり直しになる。

**3場面に共通する核心**: 詰まりは計算能力ではなく「出力の形」にある。findings §4-3① の結論通り、一次出力を「A が勝ち」から「**A の勝ちは基準 k の重みを何ポイント動かすと崩れ、それ以外では崩れない**」に置き換えることが、この3場面すべての解になる。

## 2. 中核となる計算モデルの確定

### 2-1. 加重和(WSM / SAW)を採る

**決定: 総合スコアは `S_i = Σ_j (w_j × a_ij)` とする。**

根拠は3つで、いずれも findings に直接ある。

1. **カテゴリの定義そのもの**(findings §2🔴)。「加重和 Σ(weight × score) の自動計算とライブ更新」は調査13ツール全てが実装しており、これを外すと決定マトリクスツールを名乗れない。
2. **理論的裏付けが確立している**(findings §3-1)。WSM は最も基本的な MCDM 手法であり、onlinetoolhubs はこれを MAUT の線形結合と明記している(findings §1-B)。SMART(Edwards 1977)、Swing weighting(von Winterfeldt & Edwards 1986)も同じ加法的多属性効用関数の枠内にある。
3. **感度分析が閉形式で解ける**。これが決定的である。天秤の中核価値は §3 の逆転閾値であり、加重和は w について線形・a について線形なので、後述の通り Δw が**反復計算なしの閉じた分数式**になる。findings §2🟡 が見送りとした TOPSIS では近接係数 `s_iw = d_iw/(d_iw+d_ib)`(findings §3-3)が距離の比になるため w に対して非線形で、閾値を数値解法でしか出せない。単一HTMLで即時応答するという制約(§4)とも、加重和が最も整合する。

### 2-2. スコア正規化方式 — **固定尺度(0-10 入力 → 内部 0-1)を採り、min-max は採らない**

**決定: 各セルはユーザーが 0〜10 の固定尺度で入力し、内部では `a_ij = raw_ij / 10 ∈ [0,1]` として保持する。表示上の総合スコアは `S_i × 100` で 0-100 に写す。基準ごとの min-max 正規化(選択肢集合内の最小値/最大値で割る方式)は採用しない。**

findings に基づく根拠:

- **観測された実装は全て固定尺度側**。findings §2🔴「スコアの正規化(0-100等の共通尺度化)」の根拠として挙がる3ツールを findings §1-B で確認すると、geratools は「加重和を0-100に正規化。スケール(0-5/0-7/0-10)選択可」、altftool は「Σ(weight × score) ÷ Σ(weights) × 10 で0-100スコア化」、chamsdel は「重み1-10 × スコア1-10 → 100点正規化」である。いずれも**ユーザーが固定尺度で入力し、出力側を100点に写している**のであって、選択肢集合から最大最小を取る min-max ではない。yesnowheelapp も 1-10 スコア(findings §1-B)。市場の既定はこちらである。
- **min-max は rank reversal を自ら作り込む**。min-max では `a_ij` が選択肢集合に依存するため、選択肢を1つ追加・削除しただけで既存選択肢の正規化スコアが動き、順位が入れ替わりうる。findings §3-3 は TOPSIS について「選択肢が近接している場合の順位逆転(rank reversal)問題」(Wang & Luo)を、findings §3-4(b) は「Rank Reversal パラドクスは多くの多基準手法に共通する問題」を明記している。天秤の一次出力は「結論の頑健性」(findings §4-3①)であり、選択肢を1件足しただけで頑健性ラベルが反転する製品は自己矛盾する。固定尺度なら `a_ij` は他の選択肢に一切依存せず、この経路の rank reversal は**構造的に発生しない**。
- **感度分析の解釈可能性**。§3 の閾値式は `d_k = a_Wk − a_Lk`(勝者と挑戦者のスコア差)に支配される。固定尺度ならこの差は「10点満点で何点差か」というユーザーが入力した値そのものであり、「通勤で5点差ついているから通勤の重みが効く」と直接説明できる。min-max ではこの差が集合依存の派生量になり、説明が一段遠くなる。

**尺度は 0-10 に固定する**(geratools のようなスケール選択は設けない)。findings §2🟡 が「一般ユーザーには手法選択自体が認知負荷」と述べる論理は尺度選択にもそのまま当たり、かつ尺度を変えても加重和の順位は不変(定数倍)なので、選択肢を提供する実利がない。

### 2-3. コスト基準の反転

**決定: 各基準に `direction ∈ {benefit, cost}` を持たせ、cost の場合 `a_ij = (10 − raw_ij)/10` とする。**

findings §2🔴 が「コスト基準の反転(低いほど良い)」を必須に置き、根拠として geratools の実装(findings §1-B「コスト基準の自動反転。『低いほど良い』と『高いほど良い』を1つの表に混在可」)と「価格・時間・リスクは実務でほぼ必ず登場するため、これがないと手作業で逆数化が必要になる」を挙げている。

反転の実装として**逆数化(1/x)ではなく尺度上の補数(10 − x)を採る**。逆数は非線形で 0 付近が発散し、加重和の線形性 —— すなわち §3 の閉形式が成立する前提 —— を壊すためである。補数変換なら `a_ij` は依然 [0,1] に収まり、集合非依存性も保たれる。

### 2-4. 重み正規化

**決定: 内部の重みは常に `w_j ≥ 0, Σ_j w_j = 1` に正規化する。UI 上は 0-100% で表示・入力し、1つを動かすと残りが比例配分で追従する。**

findings §2🔴「重みの100%への自動正規化」が根拠で、yesnowheelapp / altftool / 1000minds が明示採用、1000minds は「重みは通常合計1(100%)に正規化される」と記述(findings §3-1「重みの正規化」、出典 6)。altftool は「1つ上げると他が比例して下がる」挙動まで実装している(findings §1-B)。

この**比例再正規化**は §3 の感度分析の前提と同一の操作であり(findings §3-4(c)「単一基準の重みを1つずつ動かし、残りの重みは比例配分で差し引く(合計100%を保つ)」)、UI のスライダー挙動と逆転閾値の計算モデルが完全に一致する。ユーザーがスライダーを閾値まで動かすと、画面上で本当に順位が入れ替わる —— この一致は仕様として保証する。

## 3. 感度分析の定式化 ★最重要

### 3-0. 記号と前提

| 記号 | 定義 |
|---|---|
| `n` | 基準数、`j = 1..n` |
| `m` | 選択肢数 |
| `w_j` | 基準 j の重み。`w_j ≥ 0`, `Σ_j w_j = 1` |
| `a_ij` | 選択肢 i の基準 j における正規化スコア、`∈ [0,1]`(§2-2, §2-3 で確定) |
| `S_i` | 総合スコア `S_i = Σ_j w_j a_ij` |
| `W` | 現在の1位(勝者)、`L` | 比較対象の挑戦者(既定では2位) |
| `D₀` | 現行の勝ち幅 `D₀ = S_W − S_L > 0` |
| `d_k` | 基準 k における勝者の優位 `d_k = a_Wk − a_Lk`(符号付き。負なら挑戦者が勝っている) |

**前提(明示)**: 基準 k の重みだけを `w_k → x` に変え、**他の全基準の重みは比例再正規化される**。すなわち

```
w_j(x) = w_j × (1 − x) / (1 − w_k)     (j ≠ k)
w_k(x) = x
```

この写像は `Σ_j w_j(x) = x + (1−x)/(1−w_k) × Σ_{j≠k} w_j = x + (1−x)/(1−w_k) × (1−w_k) = 1` を常に満たす。`w_k < 1` を仮定する(ある基準が単独で100%なら他基準は存在しないに等しく、感度分析は自明)。この「残りは比例配分で差し引く」操作は findings §3-4(c) が記録した yesnowheelapp の挙動と同一であり、findings §2🔴・§3-1 の重み正規化要件とも一致する。

### 3-1. 逆転閾値の閉形式導出

摂動後のスコアは

```
S_i(x) = x · a_ik + (1 − x)/(1 − w_k) · T_i        ただし T_i = Σ_{j≠k} w_j a_ij = S_i − w_k a_ik
```

勝者と挑戦者の差を `D(x) = S_W(x) − S_L(x)` と置く。`T_W − T_L = (S_W − S_L) − w_k(a_Wk − a_Lk) = D₀ − w_k d_k` なので

```
D(x) = x · d_k + (1 − x)/(1 − w_k) · (D₀ − w_k d_k)      … (1)
```

`D(w_k) = w_k d_k + (D₀ − w_k d_k) = D₀` で現行値に一致する(検算1)。逆転が起きる境界は `D(x*) = 0`。式(1) の両辺に `(1 − w_k) > 0` を掛けて

```
x · d_k (1 − w_k) + (1 − x)(D₀ − w_k d_k) = 0
x · d_k (1 − w_k) + D₀ − w_k d_k − x·D₀ + x·w_k d_k = 0
x · [ d_k(1 − w_k) + w_k d_k − D₀ ] + (D₀ − w_k d_k) = 0
```

角括弧内は `d_k − d_k w_k + w_k d_k − D₀ = d_k − D₀`。よって

```
x (d_k − D₀) = −(D₀ − w_k d_k)
```

**逆転が起きる重み値(閉形式)**

```
        D₀ − w_k · d_k
x*_k = ─────────────────           (d_k ≠ D₀)
           D₀ − d_k
```

求める最小変化量 `Δw_k = x*_k − w_k` は

```
            D₀ − w_k d_k − w_k(D₀ − d_k)     D₀ − w_k d_k − w_k D₀ + w_k d_k
Δw_k = ──────────────────────────────── = ─────────────────────────────────
                  D₀ − d_k                            D₀ − d_k
```

分子の `−w_k d_k` と `+w_k d_k` が消えて `D₀(1 − w_k)` が残る。すなわち

> ### ★ 逆転閾値(tipping point)
> ```
>            D₀ · (1 − w_k)
>   Δw_k = ──────────────────        D₀ = S_W − S_L ,  d_k = a_Wk − a_Lk
>             D₀ − d_k
> ```
> 新しい重みは `w_k* = w_k + Δw_k`。`Δw_k > 0` なら重みを**上げる**と逆転、`Δw_k < 0` なら**下げる**と逆転。UI 表示は `|Δw_k| × 100` ポイントと方向。

分子 `D₀(1 − w_k) > 0` は常に正なので、**符号は分母 `D₀ − d_k` だけで決まる**。

### 3-2. 境界条件 — 逆転が起こり得ない場合(支配的優位)

重みは `x ∈ [0, 1]` の範囲しか取れないため、`x*_k` がこの区間外なら逆転は実行不能である。

**(i) `d_k = D₀` のとき**: 式(1) に代入すると `D(x) = x D₀ + (1−x)(D₀ − w_k D₀)/(1−w_k) = x D₀ + (1−x) D₀ = D₀`。差は x に依らず一定で、**この基準の重みをどう動かしても勝ち幅は 1 ミリも動かない**。閉形式は分母0で定義されず、`Δw_k = ∞` と解釈する。

**(ii) 上方向の実行可能性(`x* ≤ 1`)**: `Δw_k ≤ 1 − w_k` ⟺ `D₀(1−w_k)/(D₀−d_k) ≤ 1−w_k`。`D₀ − d_k > 0` の場合、両辺を `(1−w_k) > 0` で割って `D₀/(D₀−d_k) ≤ 1` ⟺ `d_k ≤ 0`。`d_k = 0` は `x* = 1`(重みを基準 k に全振り)で `D(1) = d_k = 0` すなわち**同点**にしかならない。よって**厳密な逆転には `d_k < 0` が必要**。直観と一致する: 挑戦者がその基準で勝っているからこそ、その基準を重くすれば逆転する。

**(iii) 下方向の実行可能性(`x* ≥ 0`)**: `x* = (D₀ − w_k d_k)/(D₀ − d_k) ≥ 0`。この向きが意味を持つのは `D₀ − d_k < 0` すなわち `d_k > D₀` のときで、分母が負なので条件は分子 `D₀ − w_k d_k ≤ 0` ⟺ **`w_k · d_k ≥ D₀`**。これは `D(0) = (D₀ − w_k d_k)/(1 − w_k)` の符号条件そのもの、つまり「基準 k を完全に捨て去った(重み0)時点で挑戦者が追い越しているか」である。なお `w_k d_k > D₀` かつ `w_k < 1` なら `d_k > w_k d_k > D₀` が自動で従うので、条件は `w_k d_k > D₀` だけで閉じる。

> ### ★ 実行可能性(基準 k で1位と挑戦者を逆転させられるか)
> ```
> 逆転可能 ⟺  d_k < 0        (上げて逆転: Δw_k > 0)
>          または  w_k · d_k > D₀   (下げて逆転: Δw_k < 0)
>
> 支配的優位(逆転不能) ⟺  0 ≤ d_k  かつ  w_k · d_k ≤ D₀
> ```
> 支配的優位のときは `Δw_k = ∞`(感度係数 0)とし、UI には findings §3-4(c) の yesnowheelapp と同じ形式で理由を書く: 「勝者がこの基準でも勝っており(または差が僅少で)、重みを動かしても勝ち幅が広がるだけ」。

これは findings §3-4(a) の Triantaphyllou & Sánchez の枠組みと同型である。同論文は感度係数を `sens(a_i, j) = 1/Δ'_i,j`(臨界度の逆数)と定義し、**臨界度が実行不能なら感度係数は0**とする。天秤も `sens_k = 1/|Δw_k|`、実行不能なら `sens_k = 0` を採る。

### 3-3. 反直感的洞察が式から出ることの確認

`Δw_k = D₀(1−w_k)/(D₀ − d_k)` において、`w_k` は分子に `(1 − w_k)` としてしか現れず、その効果は高々 (1−w_k) 倍にすぎない。一方 `d_k` は分母に直接入り、`d_k` が大きく負であるほど分母が膨らみ `Δw_k` は急速に小さくなる。したがって**重みが小さくてもスコア差が大きい基準は、重みが大きくスコア差が小さい基準より critical になりうる**。これは findings §3-4(a) が引用する「最も重みの大きい基準が最も重大とは限らず、最も重みの小さい基準が最も重大でありうる」(Winston 1991 への反証)を、天秤の式が構造として再現していることを意味する。findings §4-3② が「この製品の最も強い体験になる」と述べた瞬間は、この分母項が生む。

### 3-4. 複数の挑戦者への一般化と、基準の臨界度ランキング

上記は1位 `W` と特定の挑戦者 `L` の一対比較である。1位の座が崩れる真の閾値は、**全ての挑戦者に対する閾値のうち最小のもの**である。挑戦者 i について `D₀^(i) = S_W − S_i`、`d_k^(i) = a_Wk − a_ik` とすると

```
                           D₀^(i) · (1 − w_k)
Δw_k = min | ────────────────────────── |     ただし実行可能な (k, i) のみ
      i≠W    argmin        D₀^(i) − d_k^(i)
```

計算量は `n × (m−1)` 通り(1位が関わるペアのみ)で、findings §3-4(a) が示す総当たり `2 × (N × M(M−1)/2)` の部分集合である。天秤は「1位が崩れるか」だけを問うので全ペアを回す必要はないが、**選択肢10・基準10でも高々90ケースの分数計算**であり、単一HTML内で即時に回る(§4)。

**基準の臨界度ランキング**は `|Δw_k|` の昇順に基準を並べたもの。実行不能な基準は末尾に「逆転不能」として置く。これが findings §2🟠・§4-3② の「どの基準が結論を支配しているかのランキング表示」の実体である。

### 3-5. 基準貢献度%

findings §3-4(d) は「選択肢 i の総スコア `Σ_j (w_j × a_ij)` に対して各項 `w_j × a_ij` が占める割合が貢献度%になる」とし、同時に**この分解式そのものを明記した一次資料は未確認**であることを明示している(findings §5「未確認事項」にも再掲)。この但し書きに従い、天秤は2種類の貢献度を定義し、どちらも「学術的に検証された指標」とは称さない。

**(A) スコア貢献度(findings §3-4(d) の定義そのまま)** — 選択肢 i ごとに

```
           w_j · a_ij               n
c_ij = ─────────────────  ,        Σ  c_ij = 1
        Σ_j' w_j' · a_ij'          j=1
```

`S_i > 0` のとき定義。全セル 0 で `S_i = 0` のときは `c_ij` を未定義とし、UI では「—」を表示する。これが SpiceLogic の weighted criteria attribute chart(findings §1-A・§3-4(d))に対応する表示で、findings §2🟠 の通り Web の無料層はゼロ。

**(B) 勝敗貢献度(天秤の一次出力用)** — 1位 W と挑戦者 L の**勝ち幅 D₀ の分解**

```
        w_j · d_j              n
g_j = ────────────  ,         Σ  g_j = 1     (D₀ ≠ 0)
           D₀                 j=1
```

`Σ_j w_j d_j = Σ_j w_j(a_Wj − a_Lj) = S_W − S_L = D₀` より恒等的に総和1。`g_j < 0` の基準は「勝者がそこでは負けているが押し切られている」ことを意味し、UI では逆符号のバーで表示する。(A) が「この選択肢が良く見える理由」を説明するのに対し、(B) は「**なぜ勝者が勝ったのか**」を説明するもので、天秤の一次出力(findings §4-3①)に直結する。(B) は (A) と同じ線形分解を差分に適用しただけの代数的恒等式であり、findings に典拠を持つ主張としては扱わない。

§3-2 の支配的優位条件 `w_k d_k ≤ D₀` は `g_k ≤ 1` と同値である —— 「その基準ひとつで勝ち幅の全部を説明できない限り、その基準を捨てても勝者は変わらない」。貢献度と逆転閾値は同じ量の2つの顔である。

### 3-6. 頑健性ラベルの判定条件

findings §3-4(c) は yesnowheelapp の判定基準を「どの単一基準でも逆転しない場合は結論を **"robust"** とラベル付けする」と記録している。これを下限として、閾値付きの3段階に拡張する。

```
Δ* = min_k |Δw_k|          (実行可能な基準のみ。1つも無ければ Δ* = ∞)
k* = argmin_k |Δw_k|       (最も critical な基準)
```

> ### ★ 頑健性ラベル
> ```
> robust      ⟺  Δ* = ∞
>                (全ての基準が支配的優位 = どの単一基準の重みを 0〜100% の
>                 どこに動かしても1位は入れ替わらない)
>
> fragile     ⟺  Δ* ≤ θ           既定 θ = 0.10 (10 ポイント)
>
> contingent  ⟺  θ < Δ* < ∞       (上記いずれでもない)
> ```

- **robust の定義は findings §3-4(c) の記述そのもの**であり、これが「決めていい」という許可を与える最終出力になる(findings §2🟠)。
- **θ = 0.10 は経験則であり、理論的裏付けを持たないことを UI 上でも明示する。** 根拠は findings §3-4(c) の実例で、yesnowheelapp は 8.5 ポイントのシフトで逆転する事例を「7.4 対 7.1 で決着した判定ではなく、真に僅差の決定である」と総括している。観測された唯一の実例(8.5pt)を fragile 側に含める最小の切りの良い値が 10 ポイントである。findings §1-B が chamsdel の「5点差以内なら僅差」ルールを「経験則で理論的裏付けなし」と切っている以上、天秤も自分の閾値を理論的裏付けありと偽ってはならない。**θ はユーザーが変更可能な設定とし、既定値の由来(yesnowheelapp の 8.5pt 事例)をツールチップに書く。**
- ラベルは必ず**理由文とセット**で出す。findings §4-3① が求める一次出力の形は「A の勝ちは Location の重みを 8.5 ポイント動かすと崩れる。それ以外の基準では崩れない」であり、ラベル単独では要件を満たさない。テンプレート: 「**{W} の1位は、{k*} の重みを {w_k*}% から {x*}%({±Δ}ポイント)に動かすと {L} に入れ替わります。他の {r} 個の基準では単独で逆転しません。**」

### 3-7. 数値検算(1例、全式に代入)

**入力**(基準4・選択肢2、スコアは 0-10 入力、内部 `a = raw/10`)

| 基準 | 向き | w_j | Job A | Job B |
|---|---|---|---|---|
| 給与 | benefit | 0.40 | 6 | 9 |
| 通勤 | benefit | 0.10 | 9 | 4 |
| 成長 | benefit | 0.35 | 8 | 7 |
| 待遇 | benefit | 0.15 | 7 | 7.5 |

**総合スコア**
```
S_A = .40(.6) + .10(.9) + .35(.8) + .15(.70) = .240+.090+.280+.1050 = 0.7150
S_B = .40(.9) + .10(.4) + .35(.7) + .15(.75) = .360+.040+.245+.1125 = 0.7575
```
勝者 W = **Job B**、挑戦者 L = Job A、**D₀ = 0.7575 − 0.7150 = 0.0425**。
`d_j = a_Bj − a_Aj` = 給与 +0.3、通勤 −0.5、成長 −0.1、待遇 +0.05。

**実行可能性(§3-2)**
- 給与: `d>0` かつ `w·d = 0.40×0.3 = 0.120 > 0.0425` → 下げて逆転可能
- 通勤: `d = −0.5 < 0` → 上げて逆転可能
- 成長: `d = −0.1 < 0` → 上げて逆転可能
- 待遇: `d = +0.05 ≥ 0` かつ `w·d = 0.15×0.05 = 0.0075 ≤ 0.0425` → **逆転不能(支配的優位)**

**閾値(§3-1)**
```
通勤: Δ = 0.0425 × (1−0.10) / (0.0425 − (−0.5)) = 0.038250 / 0.542500 = +0.070507  → w* = 17.05%  (+7.05pt)
給与: Δ = 0.0425 × (1−0.40) / (0.0425 −   0.30 ) = 0.025500 / (−0.257500) = −0.099029 → w* = 30.10%  (−9.90pt)
成長: Δ = 0.0425 × (1−0.35) / (0.0425 − (−0.1)) = 0.027625 / 0.142500 = +0.193860  → w* = 54.39%  (+19.39pt)
待遇: 逆転不能 (Δ = ∞)
```

**代入検算 — 通勤 x* = 0.170507 を式(1)ではなく元のモデルに戻して確認**
比例係数 `(1−x*)/(1−w_k) = 0.829493/0.900000 = 0.921659`。
```
w' = 給与 .40×.921659 = .368664 , 通勤 .170507 , 成長 .35×.921659 = .322581 , 待遇 .15×.921659 = .138249
Σ w' = .368664 + .170507 + .322581 + .138249 = 1.000001 ≈ 1  ✓(正規化保存)

S_A' = .368664(.6) + .170507(.9) + .322581(.8) + .138249(.70)
     = .221198 + .153456 + .258065 + .096774 = 0.729493
S_B' = .368664(.9) + .170507(.4) + .322581(.7) + .138249(.75)
     = .331797 + .068203 + .225806 + .103687 = 0.729493
S_A' − S_B' = 0.000000  ✓ 厳密に同点 = 逆転の境界
```
給与 `x* = 0.300971`、成長 `x* = 0.543860` も同様に代入すると、それぞれ `S_A' = S_B' = 0.735922`、`S_A' = S_B' = 0.741228` で**差 0**(有理数演算で厳密に一致することを確認済み)。加えて通勤について x を 0.160→0.180 まで振ると差 `S_B'−S_A'` は +0.00633 → +0.00031 → −0.00271 と符号が反転し、根が `0.170 < x* < 0.175` に挟まれる —— 閉形式の値 0.170507 と一致する。

**臨界度ランキング(§3-4)**: 通勤 7.05pt < 給与 9.90pt < 成長 19.39pt < 待遇 ∞
→ **最も重みが小さい「通勤」(10%)が最も critical**。findings §3-4(a) / §4-2-2 の反直感的洞察が、この入力で実際に現れている。

**勝敗貢献度(§3-5 B)**: `g_j = w_j d_j / D₀`
```
給与 = .40(.30)/.0425 = +2.824 (282.4%)
通勤 = .10(−.50)/.0425 = −1.176 (−117.6%)
成長 = .35(−.10)/.0425 = −0.824 (−82.4%)
待遇 = .15(.05)/.0425 = +0.176 (+17.6%)
                        合計 = 1.000  ✓
```
「Job B は給与だけで勝ち幅の 282% を稼ぎ、通勤で 118% 吐き出している」という読み。給与の `g = 2.824 > 1` は §3-5 の同値性通り「給与は単独で逆転可能」を意味し、待遇の `g = 0.176 ≤ 1` は「逆転不能」を意味する —— §3-2 の実行可能性判定と完全に一致する(相互検算)。

**頑健性ラベル(§3-6)**: `Δ* = 0.0705 ≤ θ = 0.10` → **fragile**。
出力文: 「**Job B の1位は、通勤の重みを 10% から 17.1%(+7.1ポイント)に動かすと Job A に入れ替わります。給与を 30.1% まで下げても同じことが起きます。待遇の重みは単独では結論を変えません。**」

## 4. 制約と非機能要件

### 4-1. 教主の範囲確定に由来する制約(前提)

| 制約 | 内容 | findings 上の裏付け |
|---|---|---|
| 単一HTMLファイル | HTML/CSS/JS を1ファイルに同梱。ビルド不要、ダブルクリックで動く | findings §2🔴「ログイン不要・ブラウザ内完結」— 無料Webツール8つ中7つが最大の訴求点 |
| 外部CDN禁止 | フォント・チャートライブラリ・アイコンを含め一切の外部取得なし | 同上。findings §1-B が chamsdel「サーバー送信なし」・onlinetoolhubs「100%クライアントサイド」・Argumentree「完全ブラウザ内処理」を訴求点として記録 |
| ネットワーク送信ゼロ | fetch / XHR / beacon / form action を一切持たない | 同上 |
| サーバ・ログインなし | アカウント概念を持たない | findings §1-A の対極。1000minds は必ず onboarding call を経る |
| 永続化は localStorage のみ | 保存・履歴・復元は全て localStorage | findings §4-2-3「無料ツール群のセールスポイント『サーバーに何も送らない・登録不要』は、裏返すと結果を保存も共有もできない」。天秤はこの裏返しを埋める |

**描画は依存ライブラリなしで行う。** 貢献度バー・臨界度ランキングは CSS の幅指定と inline SVG で足りる。findings §1-B の onlinetoolhubs はレーダーチャートを持つが、findings §4-1 の分析軸は「感度分析の実装」であってチャートの豪華さではない。

**「永続URL共有」の扱い**: findings §2🟠 は「結果の永続URL共有 / エクスポート」を差別化に挙げるが、サーバなし制約下で永続URLは実現できない。**エクスポート側(CSV / Markdown / JSON)のみ採用**する。findings §1-B の通り geratools のみが CSV/Markdown/JSON エクスポートを実装しており、ここは同等機能で追いつく。URL共有はハッシュフラグメントへの状態エンコードで技術的には可能だが、findings に「URLに状態を載せる実装」の観測事実がないため v1 では扱わない(§6)。

### 4-2. 入力規模の上限

findings §2🟡 は多階層サブ基準の見送り理由として「1000minds は『基準が増えるほど回答者が圧倒される』と警告し、**複数ツールが基準3-6個を推奨**」と記録し、findings §1-B は yesnowheelapp が避けるべき失敗として「**基準6-7個超で重複**」を挙げていると記録している。

| 対象 | 推奨 | ソフト警告 | ハード上限 | 根拠 |
|---|---|---|---|---|
| 基準数 `n` | **3〜6** | **7個目を追加した時点で警告**「基準が重複していないか確認してください」 | **10** | 上記 findings §2🟡・§1-B の記述に直接依拠。7個目で警告するのは yesnowheelapp の「6-7個超で重複」の記述に合わせたもの |
| 選択肢数 `m` | **2〜6** | 7件目で「比較しきれていない選択肢がないか」 | **10** | **findings に選択肢数の推奨値の記述はない。** 基準側の認知負荷論(1000minds「回答者が圧倒される」)を対称に適用した天秤側の判断であり、findings 由来の事実ではない |

**下限**: `m ≥ 2` かつ `n ≥ 1`。`m = 1` では順位も感度分析も定義されない。`D₀ = 0`(完全同点)の場合は逆転閾値が定義されないため、ラベルを出さず「同点です。基準またはスコアを見直してください」と表示する。

**計算量**: §3-4 より最悪 `n × (m−1) = 10 × 9 = 90` 個の分数計算。全て O(1) の四則演算で、キー入力ごとの全再計算でも人間の知覚閾値(<16ms)を余裕で下回る。findings §2🟡 が Monte Carlo を見送った判断(「決定論的な重みスイープで十分に答えられる」)は、この計算量特性と整合する。

### 4-3. アクセシビリティ

findings に a11y 要件の直接記述はない(**この節は findings 由来の事実主張ではなく、単一HTML制約下で満たすべき技術要件として天秤側が定める**)。ただし findings §4-3① が求める一次出力が「順位」ではなく「頑健性の文章」である以上、**結論は必ずテキストとして読める**必要があり、これは a11y と同じ方向を向く。

- 結論・逆転閾値・ラベルは**すべて素のテキストで表現**する。色やバーの長さだけで意味を伝えない(貢献度バーには必ず数値ラベルを併記)。
- グリッドは `<table>` で組み、行/列に `<th scope>` を付ける。スコア入力は `<input type="number" min="0" max="10" step="0.5">` で、`aria-label` に「{選択肢}の{基準}のスコア」を持たせる。
- 頑健性ラベルの更新は `aria-live="polite"` の領域に流し、スクリーンリーダー利用者が重みを動かした結果を追えるようにする。
- robust/fragile/contingent は色に加えて**語とアイコン形状**で区別する(色覚特性への配慮)。
- 全操作がキーボードだけで完結する。スライダーは `<input type="range">` を使い、矢印キーで 1 ポイント刻み、数値直接入力も併設する(findings §1-A の SpiceLogic が「スライダーを動かすと即座に再計算」を売りにしている挙動を、キーボードでも再現するため)。
- ブラウザのズーム 200% でレイアウトが破綻しない。

### 4-4. データとプライバシー

- localStorage のキーは `tenbin.v1.*` の名前空間に閉じる。保存内容は選択肢名・基準名・重み・スコア・重み編集履歴(§5-3)のみ。
- **「保存されていること」と「どこにも送信されていないこと」を UI 上で明示する。** findings §1-B の通り、この層のユーザーはサーバー送信の有無を最大の判断材料にしている。
- 全消去ボタンを必ず設ける。

## 5. リスクと落とし穴

### 5-1. 補償性(compensatory)の問題

**findings の指摘**(§3-1): UK政府 Analysis Function の MCDA ガイドは加重和系を "classic compensatory MCDA" と呼び、「**ある基準の好成績が別の基準の悪成績を埋め合わせてしまう**」性質を明示的な注意点とする。対策として「各基準に絶対的な最低ラインを設け、**分析前に選択肢を除外する**」ことを示唆。findings §3-4(e) はさらに、選好閾値・veto の考え方(「ある選択肢がたった1つの基準でも veto 値以上に劣るなら、他の基準での成績にかかわらず outrank できない」)を記録している。

**天秤が取る対策**:
1. **基準ごとの任意の「最低ライン(足切り値)」を持たせる。** UK政府ガイドが示唆する通り、これは加重和の**前段**で効かせる —— 最低ラインを下回る選択肢はランキングから除外し、「{基準}が最低ライン{v}を下回るため除外」と理由を表示する。加重和の中に veto を織り込むのではなく、集合を絞ってから加重和を回す設計にすることで、§2-1 の線形性と §3 の閉形式が壊れない。
2. **既定では最低ラインを設定しない。** findings §2🟡 の「一般ユーザーには手法選択自体が認知負荷」に従い、必要な人だけが使う任意機能とする。
3. **§3-5(B) の勝敗貢献度が補償の実態をそのまま可視化する。** 上の検算例で「給与 +282%、通勤 −118%」と出る表示は、まさに「給与の好成績が通勤の悪成績を埋め合わせている」ことの数値そのものである。補償性を隠さず、画面の中央に出す。

### 5-2. Rank reversal(順位逆転パラドクス)

**findings の指摘**(§3-3・§3-4(b)): Wang & Luo は TOPSIS の順位逆転問題を指摘し、近接係数 0.44 / 0.56 の2案が**選択集合を変えると順位が変わる**実例が報告されている。findings §3-4(b) は「Rank Reversal パラドクスは多くの多基準手法に共通する問題」と明記する。

**天秤が取る対策**:
1. **正規化を集合非依存にすることで、この経路を構造的に閉じる。** §2-2 の決定(固定尺度、min-max 不採用)と §2-3 の決定(逆数化ではなく補数変換)により、`a_ij` は他のどの選択肢にも依存しない。したがって選択肢を追加・削除しても既存選択肢の `a_ij` も `S_i` も変化せず、**加重和の順位は選択集合に対して不変**である。これは TOPSIS(findings §2🟡 で見送り)を採らなかったことの直接の見返りでもある。
2. **ただし「1位が入れ替わる」ことは起きる** —— 新しい選択肢が既存より高いスコアを取れば当然1位は変わる。これはパラドクスではなく正常動作なので、混同しないよう UI では「既存選択肢どうしの相対順位は変わりません」と説明する。
3. **感度分析側の rank reversal は逆に主機能として扱う。** §3 が計算しているのは「重みを動かすと順位が変わる条件」そのものであり、天秤はこれを隠すべきバグではなく**売り物**にしている(findings §4-3①)。

### 5-3. 重みの結論ありき逆算(motivated reasoning)

**findings の指摘**(§2🟠・§4-2-4): yesnowheelapp は失敗パターンとして「自分の好きな選択肢が勝つまで重みを調整していることに気づいたら、マトリクスは仕事をやめている」と明記するが、**機能として検知・警告する実装は皆無**。findings §4-2-4 は「重みの編集履歴を保持すれば技術的には検知可能」と、実装経路まで示している。

**天秤が取る対策**:
1. **重みの編集履歴を localStorage に保持する。** 各編集について `{時刻, 基準, 変更前, 変更後, その時点の1位}` を記録する。§4-1 の制約下でも localStorage だけで完結する。
2. **検知条件を明示的に定義する。** 履歴上で**1位が入れ替わった回数** `f` を数え、`f ≥ 3`(既定、設定可)に達したら警告を出す。文面: 「重みを {N} 回編集する間に1位が {f} 回入れ替わっています。結論に合わせて重みを調整していないか確認してください。」findings §4-2-4 の文言をそのまま行動可能な形に落としたもので、findings §2🟠 の通り**誰も実装していない**領域である。
3. **「最初の重み」を固定して並記する。** セッション開始時(最初に全スコアを入力し終えた時点)の重みを `w⁰` として保存し、現在の重みと並べて表示する。ユーザーが自分の移動量を常に見られる状態にする。
4. **警告であって禁止ではない。** findings §1-B の Argumentree が「これは助言ではなく、あなたの代わりに決めるものではない」と明記する立場を踏襲し、編集をブロックはしない。

### 5-4. 追加で認識しているリスク(天秤側の判断)

| リスク | 内容 | 対策 |
|---|---|---|
| 頑健性ラベル θ の恣意性 | §3-6 の θ=0.10 は経験則で理論的裏付けがない。findings §1-B は chamsdel の「5点差ルール」を同じ理由で批判している | 由来(yesnowheelapp の 8.5pt 事例)を UI に明記し、ユーザーが変更可能にする。ラベルは常に生の数値(`Δ*` のポイント数)とセットで表示し、ラベル単独で見せない |
| `D₀ = 0`(完全同点)/ `S_i = 0`(全セル0) | 閾値式・貢献度式の分母が 0 になる | §4-2 の通りラベルを出さず、専用メッセージに切り替える |
| 「robust だから正しい」という誤読 | robust は「この重みの下で結論が安定」であって「基準の選び方が正しい」ではない | robust 表示に必ず但し書きを添える: 「基準そのものが抜けている可能性は、この分析では検出できません」 |

### 6-1. AHP(ペア比較 + CR)の採否判断 — **不採用(v1スコープ外)**

findings §4-3③ は AHP の CR を3つの勝ち筋の1つに挙げ、根拠は強い(1000minds $25,000/年・TransparentChoice £4,000/年〜・SpiceLogic の独占領域、1000minds 自身が「直接レーティングは本質的に不正確でバイアスを受けるため推奨しない」と明言、n=5 なら `5×4/2 = 10` 問で UX 的に成立)。それでも v1 では採らない。理由は4つ。

1. **実装に必要な Random Index テーブルが findings に存在しない。** `CR = CI/RI`(findings §3-2)を計算するには基準数 n ごとの RI が要るが、findings が確認しているのは **n=3 の RI = 0.58 ただ1つ**(findings §3-2「実装例と具体値」)である。§4-2 で基準数の上限を 10 と定めた以上、n=4〜10 の RI を天秤が独自に持ち込むことになり、これは「findings にない事実を creating しない」という本位相の規律に正面から反する。n=3 でしか CR を出せない機能は、基準3-6個推奨(findings §2🟡)の製品として意味をなさない。
2. **閾値そのものを findings が不確実と記録している。** findings §3-2 は (a) Saaty が n=3・n=4 に 0.05・0.08 を追加提案しているが MDPI レビューの表記が 0.5/0.8 と食い違い**要一次資料確認**、(b) 基準数が増えると CR が 0.10 を超えやすく Saaty の指標には文献上の批判がある(Murphy)、(c) CR < 0.2 までを許容する立場もある(Amenta et al. 2020)—— と3重に留保を付けており、findings §5「未確認事項」にも再掲されている。**「0.1 を超えたら赤で警告」という断定的な UI を、この根拠状態で出すべきではない。**
3. **中核価値①〜④は重みの出自に依存しない。** §3 の全ての式は任意の `w`(`w_j ≥ 0, Σw_j = 1`)に対して定義されており、その `w` がスライダー由来かペア比較由来かを問わない。したがって AHP は中核価値の**前提条件ではなく代替入力モード**であり、後から追加しても既存の計算は一切変わらない。単一HTML(§4-1)という面積制約の下で、2つ目の入力モダリティは UI 表面積をほぼ倍にする割に、中核の出力を1ミリも改善しない。
4. **同じ 🟠 枠に、findings だけで完結し誰も実装していない機能がある。** 「重みの結論ありき逆算の検知・警告」は findings §2🟠 が「**機能としては誰も実装していない**」と記し、findings §4-2-4 が実装経路(重みの編集履歴)まで与えており、localStorage だけで完結する。差別化の希少性は AHP と同等以上で、根拠の完全性と実装コストで明確に勝る。限られた面積はこちらに配分する。

**再検討の条件(明記)**: Saaty の一次資料から n=4〜10 の RI テーブルと、n=3/n=4 の閾値(0.05 / 0.08)が確認できた時点で、🟠 差別化として再度俎上に載せる。その際もペア比較は**既定モードではなく任意の代替モード**とし、直接入力を既定に据える(findings §1-B の通り無料層13ツールが全て直接入力であり、ユーザーの期待値の中心はそこにあるため)。

## 付録: v1 で実装する計算の全式(実装者向けサマリ)

```
入力:  raw_ij ∈ [0,10],  dir_j ∈ {benefit, cost},  ŵ_j ≥ 0

正規化:  a_ij = raw_ij/10                (dir_j = benefit)
         a_ij = (10 − raw_ij)/10         (dir_j = cost)
         w_j  = ŵ_j / Σ_j' ŵ_j'

スコア:  S_i = Σ_j w_j · a_ij            表示は S_i × 100

順位:    W = argmax_i S_i,  挑戦者は残り全て

逆転閾値(基準 k、挑戦者 i):
         D₀ = S_W − S_i ,  d_k = a_Wk − a_ik
         実行可能 ⟺ d_k < 0  または  w_k·d_k > D₀
         Δw_k = D₀(1 − w_k) / (D₀ − d_k)      新重み w_k* = w_k + Δw_k
         実行不能なら Δw_k = ∞, sens_k = 0 ; それ以外 sens_k = 1/|Δw_k|

臨界度:  Δ*_k = min over 挑戦者 i の |Δw_k^(i)| ,  ランキングは Δ*_k 昇順
         Δ*   = min_k Δ*_k ,  k* = argmin_k Δ*_k

貢献度:  c_ij = w_j·a_ij / S_i                      (スコア貢献度, Σ_j = 1)
         g_j  = w_j·(a_Wj − a_Lj) / D₀              (勝敗貢献度,  Σ_j = 1)
         恒等: g_k ≤ 1 ⟺ 基準 k は下方向に逆転不能

ラベル:  Δ* = ∞      → robust
         Δ* ≤ θ      → fragile        (θ 既定 0.10、ユーザー変更可)
         それ以外    → contingent

逆算検知: 重み編集履歴で1位が入れ替わった回数 f ≥ 3 → 警告
```
