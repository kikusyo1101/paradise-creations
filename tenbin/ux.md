## 1. 画面の全体構造

### 1-1. ゾーンの定義と縦順序

画面は上から下へ7つの帯で構成する。**この縦順序は幅に依らず不変**であり、狭幅でも入れ替えない(R1)。

| # | ゾーン | 役割 | 主な FR |
|---|---|---|---|
| **Z0** | ヘッダ | 製品名 / プライバシー明示 / θ設定 / エクスポート / 全消去 | FR-12, FR-17, FR-16, FR-24 |
| **Z1** | **結論帯** | **一次出力**。頑健性ラベル + `Δ*` + 理由文。`aria-live="polite"` | FR-11, FR-19, FR-22 |
| **Z2** | 順位ストリップ | 二次表示。総合スコア降順 + 勝者強調 + 勝ち幅 `D₀` | FR-07 |
| **Z3** | **基準・臨界度パネル** | 基準名 / 向き / **重みスライダー(閾値マーカー内蔵)** / `Δw_k` / 逆転相手。**臨界度昇順で並ぶ** | FR-01, FR-04, FR-05, FR-08〜FR-10, FR-20 |
| **Z4** | 貢献度パネル | 勝敗貢献度 `g_j`(中心0軸バー)/ 挑戦者切替 / スコア貢献度 `c_ij` | FR-13〜FR-15 |
| **Z5** | 重み履歴帯 | 最初の重み `w⁰` との並記 / 逆算検知の警告 | FR-18 |
| **Z6** | スコアグリッド | 選択肢 × 基準の `<table>`。追加・削除・リネーム | FR-01, FR-02, FR-03, FR-21 |

**Z3 が「基準パネル」と「臨界度ランキング」を兼ねることが、本設計の最大の構造判断である。**
prd は FR-05(重みスライダー)と FR-10(臨界度ランキング)を別要件として書いているが、両者は**同じ基準の同じ重み軸の上の話**であり、別々の場所に置くと R3 の体験(「ランキングが示した数値まで、目の前のスライダーを動かす」)が視線移動で分断される。したがって**1つのパネルに統合し、行の並び順を `|Δw_k|` 昇順とする**(FR-10 / AC-06)。重複した重み UI は作らない。

> 並べ替えの副作用への対処は §5-5 に書く(編集中は並べ替えない)。

### 1-4. sticky の縮約規則

Z1 は情報量が多いので、スクロールで上端に固定される際は**1行に縮約**する。

```
▲ fragile  Δ*=6.8pt(≤10.0)  移行コスト 15.0%→21.8% で ベンダーA に逆転   [展開▾]
```

- 縮約時も **ラベル語・`Δ*` の数値・`k*` の名前**の3点は必ず残す(R2)。
- 縮約は視覚的表現の変更にすぎず、DOM 上の `aria-live` 領域は完全文のままにする(スクリーンリーダーには常に完全文が届く、§6-4)。

## 2. 一次出力の設計

### 2-1. 結論帯の解剖

Z1 は上から4段。**この4段構成は3状態すべてで不変**であり、状態によって変わるのは記号・語・帯の縁・4段目の中身だけである。

| 段 | 内容 | 根拠 |
|---|---|---|
| **① 記号 + 語 + 判定式** | `{形状アイコン} {robust\|contingent\|fragile} — {説明}(Δ* = {Δ*}ポイント {≤\|>} しきい値 {θ}ポイント)` | prd §5-1 のラベル本体テンプレートを**一字一句そのまま**使う。FR-11「ラベル単独では表示しない」への直接の対応 |
| **② 理由文** | prd §5-1 / §5-2 の正典テンプレート。`{}` のみ置換 | FR-11 / prd §7-4.10④ |
| **③ 但し書き** | robust のときのみ「基準そのものが抜けている可能性は、この分析では検出できません。」 | FR-22 / AC-17 |
| **④ Δ* 数直線** | `0` から `40pt` の固定軸上に `Δ*` の位置と `θ` の位置を打つ | FR-11 / FR-12。ラベルが「なぜその判定になったか」を1目で検証可能にする |

**④ の Δ* 数直線**は R2 の実装装置である。ラベルは `Δ*` と `θ` の大小比較でしかないので、その比較そのものを図にする。軸の上限は 40pt 固定(DS-1 の最大 `Δw` が 18.1pt、実用域を覆う)。`Δ* > 40pt` の場合は軸右端に `▶` を出し、数値ラベルで実値を示す。

```
① ▲ fragile — 結論はごく僅かな重みの差で崩れます(Δ* = 6.8 ポイント ≤ しきい値 10.0 ポイント)
②  ベンダーB の1位は、移行コストの重みを 15.0% から 21.8%(+6.8ポイント)に動かすと
    ベンダーA に入れ替わります。他の 1 個の基準では単独で逆転しません。
    価格を 26.4% まで下げても同じことが起きます。
    機能充足度を 48.1% まで上げても同じことが起きます。
    サポートの重みは単独では結論を変えません。
④  0 ├──────●──────┤──────────────────────────────┤ 40pt
            Δ*=6.8  θ=10.0                          [しきい値を変える ⓘ]
```

### 2-2. 3状態の見え方の違い

**色は identity 位相の管轄なので、ここでは「どの役割色を使うか」と「色以外で何が違うか」だけを定める(FR-26④: 色に加えて語とアイコン形状で区別)。**

| | **robust** | **contingent** | **fragile** |
|---|---|---|---|
| **アイコン形状** | **閉じた四角(錠)** ■ | **菱形** ◆ | **三角(警告)** ▲ |
| 語 | robust | contingent | fragile |
| 帯の縁 | `中立色`・縁は細い | `注意色`・縁は中 | `警告色`・縁は太い |
| 帯の面 | `面`(通常) | `面`(通常) | `面`(通常)— **背景は塗り替えない**。読みやすさを状態で犠牲にしない |
| ② 理由文 | prd §5-2 の総括文「{W} の1位は、どの単一基準の重みを 0% から 100% のどこに動かしても入れ替わりません。」 | §5-1 の正典テンプレート | §5-1 の正典テンプレート(文面は contingent と同一) |
| ③ 但し書き | **必ず表示**(FR-22) | なし | なし |
| ④ 数直線 | `Δ*` のマーカーを打たず、軸全体を `中立色` で塗り、右端に **`∞`** を置く。`θ` 目盛は薄く残す(θ を動かしても robust は変わらないことが目で分かる) | `●` が `θ` の**右**に立つ | `●` が `θ` の**左**に立つ |
| Z3 の見え方 | **全行が「逆転不能」**。★マーカーが1つも存在しない画面になる | 一部の行に ★ | 最上位行の ★ が ▼ のすぐ隣に見える(= 距離が短い)|
| Z2 勝者強調 | `強調色`・強め | `強調色` | `強調色`(同じ)。**順位表示の強さを頑健性で変えない** — 順位は二次表示であり、その信頼度は Z1 が語る | 

**contingent と fragile の文面が同一である**ことは意図的である。prd §5-1 は `Δ* < ∞` の両状態に同じテンプレートを与えており、違いは①の判定式(`≤ θ` か `> θ`)にのみ現れる。これは θ が経験則にすぎない(FR-12)という誠実さの表現でもある — **θ を動かしただけで結論文が書き換わってはならない**(AC-09: `Δ*` と `k*` は θ に依らず不変)。

### 2-3. 支配的優位(逆転不能)のときの見え方

支配的優位は**2つの粒度**で現れる。混同させない。

**(a) 基準単位の支配的優位**(AC-07 サポート。他に逆転可能な基準がある)

Z3 の当該行が、臨界度ランキングの**末尾**に置かれ(FR-10 / AC-06)、次のように変わる。

```
④ サポート        [高いほど良い ▾]                                    [⋯]
   0%      ▼20.0                                                  100%
   ├───────█────────────────────────────────────────────────────────┤
   [■■■■■■■■■■ どこへ動かしても ベンダーB が1位 ■■■■■■■■■■■■■■■■■■■■■]
   🔒 逆転不能。ベンダーB がこの基準でも勝っている(または差が僅少)ため、
      重みを上げても ベンダーB のリードが広がるだけです。
   臨界度 —(逆転不能)
```

- **★マーカーが無い。** レール全域が単色で「ここは全部安全」を示す(AC-07 の両端点検証: 0% でも 100% でも1位は ベンダーB)。
- 文言は prd §5-2 の正典テンプレートそのまま。
- 臨界度バーは長さ0でも100%でもなく、**「—(逆転不能)」の文字**にする。長さでは `∞` を表現できない(R2)。
- Z1 の理由文には「サポートの重みは単独では結論を変えません。」が並ぶ(prd §5-1 の逆転不能列挙)。

**(b) 全基準が支配的優位 = robust**(AC-17 DS-2)

```
Z1  ■ robust — どの単一基準の重みを動かしても結論は変わりません(Δ* = 逆転不能)

    物件P の1位は、どの単一基準の重みを 0% から 100% のどこに動かしても入れ替わりません。

    基準そのものが抜けている可能性は、この分析では検出できません。

    0 ├──────────────┤──────────────────────────────────────▶ ∞
                     θ=10.0

Z3  ① 家賃      🔒 逆転不能。物件P がこの基準でも勝っている(または差が僅少)ため、…
    ② 通勤時間   🔒 逆転不能。物件P が…
    ③ 環境      🔒 逆転不能。物件P が…
    (★マーカーが画面上に1つも無い)

Z4  家賃      ┊██████ +27.1%       ← 全て正、全て 100% 線の内側
    通勤時間   ┊██████████ +47.5%
    環境      ┊█████ +25.4%
```

**robust のとき、Z3 の並び順は入力順に戻す**(全基準の `|Δw_k|` が `∞` で同値のため、臨界度昇順に意味がない)。並び基準セレクタの表示も「臨界度」から「入力順(全て逆転不能)」に自動で切り替え、なぜ並べ替えが効いていないかを言葉で示す。

**robust の帯を「祝福」として演出しない。** ③の但し書きが同じ帯の中にある以上、達成感を煽る表現(紙吹雪・チェックマークの拡大アニメーション等)は禁止する。robust は「この重みの下で安定」でしかない(analysis §5-4)。

## 3. 主要フロー

### 3-1. 段階と、各段階で画面が語ること

#### ① 初回起動 / 再訪(FR-16, US-10, US-13)

- **再訪時**: `localStorage` に `tenbin.v1.*` があれば**無言で復元**する(AC-22)。「復元しました」のトーストは Z5 の履歴帯に1行だけ静かに出す(`前回 {日時} の続きです`)。**モーダルで確認を求めない** — 復元は US-10 が要求した既定動作であり、確認は摩擦でしかない。
- **初回**: 空の状態で開く。Z0 のプライバシー文(prd §5-5)は**初回も再訪も常時表示**(AC-25 の「常時表示されていること」)。
- 初回は Z3/Z4/Z5 を**存在ごと隠す**。理由: 空のパネルの骨組みだけを見せても意味がなく、「何をすればいいか」の視線が散る。Z1 が空状態文言を持ち、Z6 が入力を待つ。

#### ② 空状態(FR-19, prd §5-3)

Z1 の②の位置に、prd §5-3 の文言を**そのまま**置く。詳細は §7-1 の表。
初回の Z1 は次の形になる。

```
Z1  まず、比べたいものを2つ以上足してください。
    [+ 選択肢を足す]        ← Z6 の追加ボタンにフォーカスを送るショートカット
Z6  (空のグリッド枠と [+ 選択肢を足す] [+ 基準を足す])
```

**空状態の Z1 にはラベル記号も Δ* 数直線も出さない。** 何も計算できていないのに帯の骨格だけあると、「まだ判定していない」ことが伝わらない。

#### ③ 基準の設定(FR-01, FR-02, FR-04, FR-05, FR-20)

基準を足すと Z3 が現れる。**この段階では Z3 は「臨界度ランキング」ではなく「重み設定パネル」として振る舞う** — スコアが未入力なので `Δw_k` が計算できないためである。

- 行は**入力順**に並ぶ。並び基準セレクタは「臨界度」を選べるが `disabled` で、理由を添える: `採点が終わると崩れやすい順に並べ替えられます`。
- 重みスライダーのレールには **★マーカーが出ない**。代わりにレール下に `採点が終わると、ここに「逆転する重み」の目印が出ます` を1度だけ表示する(全セル入力完了後は消える)。
- 向きトグルは**この段階で目立たせる**。コスト基準の指定漏れは勝者そのものを変える(AC-14: ベンダーB → ベンダーA)ため、§5-4 の措置を取る。
- 7個目の基準を足した瞬間、`基準が重複していないか確認してください。`(prd §5-3)を追加ボタンの直下にインライン表示。**追加はブロックしない**(FR-02)。

#### ④ 選択肢とスコアの入力(FR-01, FR-03, FR-06, FR-21)

- 選択肢を足すたび Z6 に行が増える。2件目が入った瞬間 Z2(順位)が現れる。
- **未入力セルが1つでもある間、Z1 は結論を出さない。** `未入力のセルが {c} 個あります。埋めるまで結論は出せません。`(prd §5-3)。`{c}` は入力のたびに減り、この数字自体が進捗インジケータとして働く。
- ただし **Z2(順位)と Z6 の再計算は未入力があっても走らせる**(未入力セルは `0` として扱わず、その選択肢の総合スコアを `—` とする)。全ての選択肢が埋まった行から順にスコアが立ち上がるので、「入力が結果に効いている」感覚(US-03)が最初の1セルから得られる。
- 選択肢追加時、Z6 の下の rank invariance 説明文(prd §5-6)が **1回だけ点灯**する(reduced-motion 時は点灯せず常時表示、§8)。AC-20 の「1位が D に変わることは正常動作」の予防的説明。

#### ⑤ 採点完了 → 結論の成立(FR-06〜FR-11)

最後の未入力セルが埋まった瞬間、次が**同時に**起きる。

1. Z1 が空状態文言から**結論帯**に変わる(ラベル+`Δ*`+理由文+数直線)。`aria-live` が完全文を読み上げる。
2. Z3 が**臨界度昇順に並べ替わり**、各レールに **★(逆転する重み)マーカーが打たれる**。
3. Z4 が現れる(勝敗貢献度・スコア貢献度)。
4. その時点の重みが **`w⁰`(最初の重み)として確定・保存**される(FR-18: 「最初に全スコアを入力し終えた時点」)。Z5 に `最初の重み: …` の並記が現れる。

**この瞬間が製品の山場である。** ②→⑤ の遷移は §8-2 のモーション規則に従い、`Δ*` 数直線の `●` とレールの ★ だけが動きで注意を引く。

#### ⑥ 結論を読む・触る(FR-08〜FR-15, FR-18)

ユーザーはここで3つの動きのどれかをする。すべて Z3 で完結する。

- **読むだけ** → Z1 の理由文と Z3 の ①行(最も浅い基準)で終わる。
- **試す** → ★まで動かす。§4-4 の体験。
- **逆算する** → 好きな選択肢が勝つまで動かす。3回目の1位入替で Z5 に警告が出る(AC-21)。**警告は Z5 に出る。Z1 には出さない** — Z1 は結論の場所であり、行動の指摘で汚さない。編集はブロックしない(FR-18)。

#### ⑦ 持ち出す(FR-17, FR-16)

- Z0 の `[出力▾]` から CSV / Markdown / JSON。**3形式とも同じメニューの中にあり、押した瞬間にダウンロードが始まる**(中間ダイアログを置かない)。
- 出力後、Z0 に `{形式} を書き出しました({ファイル名})` を `aria-live="polite"` で1度通知。
- `[全消去]` は**2段階**にする(FR-16 の「全消去ボタンを必ず設ける」+ 不可逆操作の安全側)。1回目の押下でボタン自身が `本当に全部消す` に変わり、`Esc` またはフォーカス離脱で元に戻る。**モーダルは使わない**(キーボード操作の複雑さを増やさないため、AC-26)。

## 4. 感度分析の見せ方 ★最重要

### 4-0. 中核となる1つの決定

> **重みスライダーのトラックそのものを、逆転閾値の目盛盤にする。**
> `0% ─ 100%` の同一軸の上に、`▼ 現在の重み w_k`(= スライダーのつまみ)と `★ 逆転する重み w_k*` を並べて描き、その間を塗る。**塗られた長さが `|Δw_k|` そのもの**であり、臨界度ランキングとは「この塗りが短い順に行を並べたもの」に他ならない。

この1つの決定が、prd の3つの要件を同時に満たす。

- **FR-10(臨界度ランキング)**: 塗りの短い行が上に来る。DS-1 では移行コスト(6.8pt)が最上位、価格(8.6pt)が2番目 — **重みが最小の基準が、重みが最大の基準より上に来る**(AC-06 の反直感的洞察)。塗りの長短として一目で見える。
- **FR-05 / AC-10(スライダーと閉形式の一致)**: ★は「そこまで動かせ」という指示であり、実際に動かすと同点になる。指示と結果が同じ座標系にある。
- **FR-25(ライブラリなし描画)**: すべて `<input type="range">` のトラック背景に対する CSS の `linear-gradient` ハードストップと、`::before` / `::after` の絶対配置マーカーで描ける。外部グラフライブラリを一切必要としない。

### 4-1. 臨界度レールの構造

1行の完全な解剖(DS-1 の移行コスト行、AC-05 の値)。

```
① 移行コスト                     [低いほど良い ▾]                       [⋯]
   ┌ヘッダ行────────────────────────────────────────────────────────────┐
   │ 現在 15.0%  →  逆転 21.8%  (+6.8ポイント)   ベンダーA に逆転        │
   └──────────────────────────────────────────────────────────────────┘
   0%                                                                100%
   ├──────────▼══════════★──────────────────────────────────────────────┤
   │◀─ 15.0 ─▶│◀ 6.8pt ▶│                                              │
   [■■■■■■■■■■■■■■■■■■■■][─────────────────────────────────────────────]
   ← ここまで ベンダーB が1位 →← ここから ベンダーA が1位 ─────────────→
                        [閾値へ]  [元に戻す]
   臨界度 ████████████████████▏ 6.8pt  ← 最も浅い
```

| 要素 | 意味 | 描画手段(CSSのみ) |
|---|---|---|
| **レール(`├───┤`)** | 基準 k の重み `w_k` が取りうる 0%〜100% の全域。**全行で同一スケール**(行ごとにスケールを変えない — 行間の比較が壊れるため) | `<input type="range" min="0" max="100" step="0.1">` のトラック |
| **`▼`** | 現在の重み `w_k`。スライダーのつまみそのもの | range の thumb |
| **`★`** | 逆転する重み `w_k*`(FR-08)。**このマーカーがこの製品の中心である** | トラック背景の `linear-gradient` に置いたハードストップ + `::after` の小さな三角(inline SVG 可、FR-25) |
| **`══`(▼と★の間の塗り)** | `Δw_k`。**塗りの長さ = 動かすべき量** | gradient の帯 |
| **勝者ゾーン帯** | レールを `w_k*` で2分し、`[現在の勝者が1位の側]` と `[逆転相手が1位の側]` に塗り分ける | 同じ gradient の 2 ストップ。ハードストップ1つで足りる |
| **ゾーンのラベル文字** | `ここまで {W} が1位` / `ここから {逆転相手} が1位` | 通常テキスト。**帯の意味を色に頼らせない**(R2 / FR-26①) |
| **臨界度バー** | 行間の比較専用の短いバー。`|Δw_k|` を全行の最大値で正規化し、**短いほど危険**であることを `← 最も浅い` の語で補う | `width: %` の div |

**臨界度バーが「短いほど危険」という反直感的な向きになる点に注意。** バーの長さだけでは誤読されうるので、**最上位行には必ず `← 最も浅い` のラベルを付け**、パネル見出しを「基準 — **崩れやすい順**」とし、行番号 `①②③` を振る。数値(`6.8pt`)は常に併記する(R2)。

### 4-2. 3つの表示形態と、それぞれの `Δw_k` の符号

| 形態 | 条件 | レールの見え方 |
|---|---|---|
| **上げて逆転**(`Δw_k > 0`) | `d_k < 0`(FR-09) | ★が▼の**右**。塗りは右向き `▼══★`。ヘッダ文 `現在 15.0% → 逆転 21.8%(+6.8ポイント)` |
| **下げて逆転**(`Δw_k < 0`) | `w_k·d_k > D₀`(FR-09) | ★が▼の**左**。塗りは左向き `★══▼`。ヘッダ文 `現在 35.0% → 逆転 26.4%(−8.6ポイント)`。**符号は必ず表示する**(FR-10④「必ず符号付き」) |
| **逆転不能**(`Δw_k = ∞`) | `d_k ≥ 0` かつ `w_k·d_k ≤ D₀` | ★が**存在しない**。レール全域が単色 + `どこへ動かしても {W} が1位`。錠アイコン + prd §5-2 の理由文。臨界度は `—(逆転不能)` |

DS-1 の4行が、この3形態を全て含む(移行コスト=上げて / 価格=下げて / 機能充足度=上げて / サポート=逆転不能)。**この画面ひとつが AC-05 / AC-06 / AC-07 の全てを同時に表示している。**

### 4-3. 行の並びと「逆転相手」の扱い

- 並び順は `|Δw_k|` 昇順、**逆転不能な基準は末尾**(FR-10 / AC-06)。DS-1 では `移行コスト → 価格 → 機能充足度 → サポート`。
- FR-08 は全挑戦者を走査して最小の `|Δw_k|` を採るので、**行ごとに逆転相手が異なりうる**。したがって逆転相手名は**行のヘッダに必ず書く**(`ベンダーA に逆転`)。Z4 の挑戦者セレクタ(FR-15)とは無関係であり、**挑戦者を切り替えても Z3 は変わらない**(FR-15: 挑戦者の選択は貢献度表示にのみ影響する)。この独立性を誤解させないため、Z4 の挑戦者セレクタの脇に `この選択は貢献度の内訳だけを変えます。崩れやすさの計算は常に全ての選択肢を相手にしています。` を添える。

### 4-4. 「本当に入れ替わる」を体験させる(AC-10)★

R3 の核心。**3つの操作経路を用意し、どれを通っても同じ結果に着地させる。**

#### 経路A — スライダーをドラッグして ★ を越える

ドラッグ中、次が**同一フレームで**更新される(FR-06: 計算ボタンを持たない)。

1. **レールの塗り分けが、つまみの下を通り過ぎる。** ▼が★を越えた瞬間、つまみは「逆転相手が1位の側」の帯の上に乗る。**位置関係そのものが結果を予告している。**
2. Z2 の順位ストリップで1位と2位のカードが入れ替わる(§8-2 の並べ替えモーション)。
3. Z1 の結論帯が新しい勝者の文に書き換わる。
4. Z5 の逆算検知カウンタ `f` が加算される(AC-21)。

**★のちょうど上で止めたとき、画面は「同点」を表示する。** これが AC-10 の可視化である。DS-1 の移行コストを 21.8% にすると `S_A = S_B = 64.8`(AC-10)。

```
Z1  同点です。基準またはスコアを見直してください。
Z2  1位タイ ベンダーA 64.8  /  1位タイ ベンダーB 64.8  /  3位 ベンダーC 48.5
Z3  ① 移行コスト   現在 21.8%  ▼★が重なっている
    ├──────────────▼★────────────────────────────────────────────────┤
    ちょうど境目です。ここから少しでも動かすと勝者が変わります。
```

> **同点は「失敗」ではなく「到達点」として見せる。** `Δ*` の意味を身体で理解した瞬間だからである。ただし表示文言は FR-19 / prd §5-3 の `同点です。基準またはスコアを見直してください。` を**そのまま**使い、勝手な祝辞は足さない。頑健性ラベルと勝敗貢献度は表示しない(AC-18)。

#### 経路B — `[閾値へ]` ボタン(キーボード主経路)

各行に `[閾値へ]` を置く。押すと `w_k` を **`w_k*` に厳密に設定**する(表示値 21.8% ではなく内部値 `19/87` を使う — 表示丸めで同点にならない事故を防ぐ)。

- スライダーを 0.1 刻みで矢印キー操作しても厳密な `w_k*` には到達できないため、**このボタンが AC-10 のキーボード経路である**(AC-26 との整合)。
- 押した直後、同じ位置のボタンが `[元に戻す]` に変わり、**押す前の重みベクトル全体**を復元する。逆算検知(FR-18)への配慮: **`[閾値へ]` と `[元に戻す]` のペアは1往復で `f` を最大1しか増やさない**よう、`[元に戻す]` は履歴に「取り消し」として記録する。

  > 【prd 未定義 — 要確認】FR-18 は「重み編集ごとに履歴を記録」としか定めておらず、取り消し操作の扱いを規定していない。上記は「探索を促す機能が逆算警告を誤発火させる」ことを避けるための UX 側の提案であり、requirements 位相の確認を要する。確認が取れない場合の既定は **`[元に戻す]` も1回の編集として記録する**(prd の文面に忠実な側)とする。

- ボタンのラベルには数値を入れる: `[21.8% へ]`。何が起きるかをボタン自身が語る(R2)。

#### 経路C — Z1 の理由文からの直接ジャンプ

Z1 の理由文中の基準名(`移行コスト`)を、**Z3 の該当行にフォーカスを送るリンク**にする。読んで → 触る、の距離を最短にする。文の見た目は変えず、フォーカス可能にするだけ(下線等の装飾は identity 位相の裁量)。

#### 予告表示(操作前に結果を見せる)

★マーカーに**ホバー/フォーカスすると、確定操作なしで結果を先に示す**。

```
★ 21.8% ── ここに合わせると ベンダーA と同点(どちらも 64.8)になります
            さらに上げると ベンダーA が1位になります
```

キーボードでは、レール上の ★ 自体を `tabindex` 対象にはせず(タブ順を膨らませない、§6-2)、**`[閾値へ]` ボタンにフォーカスしたときに同じ予告文を `aria-describedby` で読ませる**。

### 4-5. 貢献度の見せ方(FR-13 / FR-14)

#### (B) 勝敗貢献度 `g_j` — 中心0軸バー

`g_j` は **100% を大きく超える**(AC-11: 価格 `+300.0%`)。単純な 0-100% バーでは描けない。したがって:

- **軸は中心0の双方向。** 正は右、負は左。
- **スケールは `max(1, max_j |g_j|)` で正規化**する。DS-1 なら `3.0`(価格)が全幅。
- **`100%` の位置に必ず基準線 `┊` を引き、`100% = 勝ち幅の全部` とラベルする。**
- 負のバーは `逆符号ハッチ`(CSS `repeating-linear-gradient` の斜線)で塗る。**色だけで正負を区別しない**(FR-26①)。
- 各バーに符号付き数値ラベルを必ず併記(FR-13)。

```
              −200%    −100%      0     +100%    +200%    +300%
                 │        │        │       ┊        │        │
  価格           │        │        ████████┊████████████████  +300.0%
  機能充足度      │        ▨▨▨▨▨▨▨▨│       ┊                    −85.7%
  サポート        │        │        █████   ┊                    +57.1%
  移行コスト      │ ▨▨▨▨▨▨▨▨▨▨▨▨▨▨▨│       ┊                   −171.4%
                                           ↑
                                   100% = 勝ち幅の全部
  この線を越えた基準は、それ単独で結論をひっくり返せます。→ 価格
  合計 100.0%

  この分解は、加重和の各項が総和に占める割合を示すものです。
  学術的に検証された指標ではありません。
```

**`100%` 基準線は装飾ではなく、AC-12 の恒等式の可視化である。**
analysis §3-5 の `g_k ≤ 1 ⟺ 基準 k は下方向に逆転不能` により、**この線を越えたバーを持つ基準は、Z3 で必ず `Δw_k < 0`(下げて逆転)の行になっている**。DS-1 では価格のみが線を越え、Z3 の価格行だけが `−8.6pt`(下げて逆転)である。**Z3 と Z4 が同じ事実の2つの顔であること**(analysis §3-5 末尾)を、線1本で結ぶ。

- 但し書き(prd §5-7)は**バーと同じカードの中に常時置く**。折りたたまない(prd §7-4.10②)。
- `D₀ = 0` のときは Z4(B) を丸ごと非表示にし、`同点です。基準またはスコアを見直してください。` に切り替える(FR-13 / AC-18)。

#### (A) スコア貢献度 `c_ij` — 100%積み上げ帯

選択肢ごとに1本の 100% 帯を積み上げ、各区画に基準名と `%` を書く(AC-13)。

```
ベンダーB  ┌────────┬─────────┬──────┬───┐
          │価格31.3│機能35.8 │サポ23.9│移9.0│  合計 100%
          └────────┴─────────┴──────┴───┘
ベンダーA  ┌────┬────────────┬──────┬──────┐
          │16.5│42.5        │22.0  │18.9  │  合計 100%
          └────┴────────────┴──────┴──────┘
案Z       ┌──────────────────────────────┐
          │ —   —   —   —                 │   S = 0.0 のため内訳を出せません
          └──────────────────────────────┘
```

- 区画が狭くて数値が入らない場合、**数値を帯の外(右側)に引き出す**。数値を消すことは許されない(FR-26①)。
- `S_i = 0` の行は4基準とも文字列 **`—`**(AC-19。`0%` も `NaN` も表示しない)。帯は空枠のまま残し、右に理由文を置く。
- 順序は Z2 の順位順(勝者が上)。

### 4-6. θ の変更 UI(FR-12)

Z0 の `[θ 10.0pt ▾]` と、Z1 ④ 数直線の `[しきい値を変える]` の**両方から同じポップオーバー**を開く。

│  [  10.0  ] ポイント   [− 1pt] [+ 1pt]        │

│            θ       ●Δ*=6.8                   │

## 5. 入力の人間工学

### 5-1. グリッドのタブ順(Z6)

**行優先(row-major)。** 1つの選択肢について全基準を打ち切ってから次の選択肢へ移る。これは「ベンダーAを評価し終えてからベンダーBへ」という人間の採点順と一致する。

```
[選択肢A名] → A×基準1 → A×基準2 → A×基準3 → A×基準4 → [A行メニュー]
           → [選択肢B名] → B×基準1 → … → [B行メニュー]
           → [+ 選択肢を足す]
```

| キー | 動作 | 備考 |
|---|---|---|
| `Tab` / `Shift+Tab` | 次/前のフォーカス可能要素(上記の順) | 標準 |
| `Enter` | **下のセル**(同じ基準の次の選択肢)へ | 列を縦に打ちたい人向け。最終行なら次の基準の先頭セルへ折り返す |
| `↑` `↓` | **数値の増減 0.5 刻み**(`<input type="number" step="0.5">` の標準動作) | セル移動には使わない(標準の数値入力挙動を奪わない) |
| `Ctrl+↑↓←→` | セル間移動 | 矢印を数値増減に割り当てた分の代替経路 |
| `Esc` | 編集中の値を破棄しフォーカス前の値に戻す | |

### 5-2. 数値入力の刷新タイミング

**「計算」ボタンは存在しない**(FR-06)。ただし**何を即時に更新し、何を確定時まで待つか**を分ける。これを分けないと、打鍵のたびに行が並び替わって入力できなくなる。

| 更新対象 | タイミング | 理由 |
|---|---|---|
| 総合スコア `S_i`、順位、Z1 の結論文、Z3 の `Δw_k` 数値、Z4 のバー | **`input` イベント(打鍵ごと・ドラッグ中も)** | FR-06 / US-03。90 演算で 16ms を大きく下回る(analysis §4-2) |
| Z3 の**行の並べ替え** | **`change` / `blur` / ドラッグ終了時のみ** | 打鍵中に行が動くとフォーカスとポインタの位置がずれる。並べ替え後は `aria-live` に `崩れやすい順を更新しました。1位は {k}。` を流す |
| Z2 の**カードの並べ替え** | `input` 即時 | 順位の入替はこの製品で最も見たい変化(AC-10)。位置が動いてもフォーカス対象ではないので害がない |
| ソフト警告(7個目)、逆算検知 `f` の判定 | `change` 確定時 | ドラッグ1回を数十回の編集として数えない(AC-21 は「編集3回」を単位としている) |
| `localStorage` 保存(FR-16) | `change` 確定時 + 500ms デバウンス | 打鍵ごとの書き込みを避ける。**保存済み表示**は Z0 に `保存済み` として静かに出す |

**空文字は `0` ではなく「未入力」**として扱う。`0` は「その基準で最低の評価」という意味を持つ正当な値であり、未入力と同一視してはならない(FR-19 の未入力セル数カウントが壊れる)。

### 5-3. 重みスライダーの人間工学(Z3)

- `<input type="range" min="0" max="100" step="0.1">` + **併設の数値直接入力**(FR-26⑤ / AC-26.4)。両者は双方向同期。
- **矢印キーは 1 ポイント刻み**(FR-26⑤ の明文)。`step=0.1` との差は `keydown` で吸収する(`↑↓←→` は ±1.0、`Shift+矢印` は ±0.1、`PageUp/Down` は ±10、`Home/End` は 0/100)。
- **他の基準の重みは比例再正規化で追従する**(FR-05)。追従した行は数値だけが変わり、**行は動かない**(並べ替えはドラッグ終了時、§5-2)。
- パネル末尾に `合計 100.0% ✓` を常時表示。表示丸めの都合で `100.1%` になりうる(AC-04)ため、**丸め表示の合計ではなく内部値が1であることを示す固定文言 `合計 100%(内部では常に厳密に 100%)`** を添える。

  > AC-04 は「丸め表示の合計は 100.1% になりうるが、内部値の合計は厳密に 1」と明記している。表示上の `100.1%` を見たユーザーが不具合と誤認しないための一文である。

### 5-4. コスト基準の向きの見せ方(FR-04 / AC-14)★

**向きの取り違えは勝者そのものを変える**(AC-14: ベンダーB → ベンダーA)。したがって向きは**3か所で同時に**見せる。

1. **Z3 の基準行**: トグル `[高いほど良い ▾] / [低いほど良い ▾]`。語で書く(`benefit`/`cost` という英語を画面に出さない)。
2. **Z6 の列ヘッダ**: 基準名の直下に `↓低いほど良い` / `↑高いほど良い` を**常時**表示。矢印記号と語の併記(色に頼らない)。
3. **Z6 のセル**: 生の入力値の右に、**変換後の値をゴースト表示**する。

```
│ 価格 ↓低いほど良い │
│ [ 7 ] → 3.0       │   ← 打ち込んだ 7 が、内部では 3.0 として効いている
```

このゴースト表示は AC-14 のセル単位検証値(`A=3.0 / B=6.0 / C=4.0`、`A=8.0 / B=4.0 / C=2.0`)そのものであり、**「低いほど良い、が効いていること」をユーザーが自分の目で検算できる**唯一の場所である。benefit 基準では `→` 以降を出さない(常に同値なのでノイズになる)。

向きを切り替えた瞬間、その列のゴースト値が全行同時に更新される。これが最も分かりやすい「効いている」の証拠になる。

### 5-5. 基準・選択肢の追加/削除/リネーム(FR-01 / FR-02)

| 操作 | 場所 | 挙動 |
|---|---|---|
| **基準を足す** | Z3 末尾 `[+ 基準を足す]` | 行を追加し、**新しい行の名前入力にフォーカスを移す**。重みは既定 `既存の平均` ではなく **`0%`** で入る(勝手に他の重みを動かさないため)。名前は `基準{n}` の仮名 |
| **基準を消す** | Z3 各行の `[⋯]` メニュー内 | 削除。**その基準の重みは残りの基準に比例再配分**(FR-05 の正規化を保つ)。`aria-live` に `{基準名} を削除しました。` |
| **基準の名前を変える** | Z3 の名前を直接編集(`contenteditable` ではなく `<input>`) | Z6 の列ヘッダと Z1 の理由文が同時に追従 |
| **選択肢を足す** | Z6 末尾 `[+ 選択肢を足す]` | 行を追加、名前入力にフォーカス。**スコアは空(未入力)** で入る。追加直後に prd §5-6 の rank invariance 文を点灯(§3-1④) |
| **選択肢を消す** | Z6 各行の `[⋯]` | 削除。`aria-live` に通知 |
| **7個目/7件目** | 追加ボタン直下にインライン警告 | prd §5-3 の文言そのまま。**ブロックしない**(FR-02) |
| **10 個/件目に到達** | 追加ボタンを `disabled` + 理由文 | ハード上限(FR-02)。理由文は【要文言確定】(§7-3) |

**削除の確認ダイアログは置かない。**(モーダルはキーボード操作の複雑さを増やし AC-26 に不利、かつ削除は Z6 に再入力すれば復元できる。)ただし `[⋯]` メニュー内に畳むことで誤クリックを防ぐ。

### 5-6. 足切りの入力(FR-20 / US-14 / AC-16)

任意機能なので**既定では畳む**(FR-20「既定では最低ラインを設定しない」)。Z3 各行の `[⋯]` → `最低ラインを設定` で展開。

```
① 移行コスト  [⋯ ▾]
   └ 最低ライン  [ 3.0 ]  (変換後スコアの 0〜10 尺度)  [解除]
      この基準で 3.0 を下回る選択肢は、加重和の前に除外されます。
```

除外された選択肢は **Z2(順位ストリップ)から消え、その下に除外リストとして理由文付きで残る**(prd §5-8)。

```
Z2  1位 ベンダーB 67.0   2位 ベンダーA 63.5     勝ち幅 3.5pt
    除外: ベンダーC — 移行コストが最低ライン3.0を下回るため除外
```

「消えた」のではなく「除外された」ことが常に見えている状態を保つ。除外後の再計算結果が除外前と一致する(AC-16: 固定尺度による集合非依存性)ことは、Z6 の rank invariance 文(prd §5-6)がすでに説明している。

| Z1 の理由文から該当基準へジャンプ | 理由文中の基準名に `Tab` → `Enter` | §4-4 経路C |

**マウス専用の操作を1つも作らない。** ホバーでしか出ない情報(★の予告表示、θ の由来文)は、必ずフォーカスまたは常時表示の経路を併設する(§4-4、§4-6)。

### 6-2. フォーカス順の原則

1. **DOM 順 = 視覚順 = タブ順**。`tabindex` の正値を使わない。
2. **フォーカス可能要素を増やしすぎない。** ★マーカー・レールの帯・臨界度バー・貢献度バーは**フォーカス対象にしない**(読み取り専用の図であり、同じ情報がテキストで隣にある)。代わりに `[閾値へ]` ボタンが操作の受け皿になる。
3. **フォーカスリングを消さない**(AC-26 末尾「`outline: none` で消されていない」)。identity 位相が形を決めるが、**可視であることは UX 側の非交渉要件**として本文書で固定する。
4. **並べ替えでフォーカスを失わない。** Z3 の行が並べ替わっても、フォーカス中の要素は同一 DOM ノードのまま移動させる(要素を作り直さない)。作り直す実装を採る場合は、並べ替え後に同じ基準の同じコントロールへフォーカスを復帰させる。
5. **Z1 → Z2 → Z3 → Z4 → Z5 → Z6 の順**にタブが進む。結論から入力へ、が既定の流れ(R1)。Z0 のツールバーは最初。
6. 各ゾーンの先頭に**見出し(`<h2>`)を置き**、スクリーンリーダーの見出しジャンプで移動できるようにする(タブ連打を強いない)。

### 6-4. `aria-live` の使い分けと発話量の制御

**最大の落とし穴は「重みスライダーを1ポイント動かすたびに結論文を全文読み上げてしまう」ことである。** これは実質的に使用不能を意味する。

- `aria-live` 領域は **Z1(結論)と Z5(警告)と Z0(状態通知)の3つだけ**にする。Z2・Z3・Z4 は live にしない(値は変わるが、フォーカスが当たったときに読めればよい)。
- **Z1 の live 更新は、最後の入力から 700ms 静止したときにのみ発火**させる(デバウンス)。連続操作中は無言、手が止まったら結論が読み上げられる、という挙動にする。
- **内容が変わらないときは DOM を書き換えない**(同じ文の再読み上げを防ぐ)。ラベルが `fragile` のまま `Δ*` だけ動いた場合も更新は1回に畳む。
- スライダー操作中の逐次フィードバックは、`aria-valuetext`(フォーカス中の要素自身)が担う。live 領域とは役割を分ける。
- **状態が「結論あり ↔ 空状態/同点」の間で切り替わったときは、デバウンスを待たず即時発火**する(モードの変化はユーザーが直ちに知る必要がある)。

### 6-5. その他の非機能(FR-26 / AC-26)

- **ズーム 200% で横スクロールなし**: レイアウトは `rem` ベース、Z3/Z4 の2カラムは幅で単一カラムに落ちる(§1-3 と同じ規則をズームにも適用 = コンテナクエリではなくビューポート幅基準で十分)。Z6 は狭幅形態(選択肢ごとの2列テーブル)に切り替わる。
- **色だけで意味を伝えない**の総点検箇所: ① 頑健性ラベル(形状+語)② 勝敗貢献度の正負(ハッチ+符号数値)③ レールの勝者ゾーン(文字ラベル)④ 逆転不能(錠+語)⑤ 勝者ハイライト(`1位` の語+順位番号)。**この5箇所が identity 位相への引き継ぎ事項**である。
- **文字だけで完結する読み**: 図(バー・レール)を全部無視しても、隣接するテキストだけで prd の全出力値が読める状態を保つ。これは AC-23(エクスポート内容)と同じ情報集合になる。

### 7-2. 状態の優先順位

## 8. モーションとフィードバック

### 8-1. 原則

1. **数値は動かさない。** カウントアップ/ロールアップ演出を禁止する。総合スコアは常時ライブ更新される値であり、途中の数字を見せるとそれが実在の値だと誤読される。**表示は常に現在の真値である。**
2. **動いてよいのは位置と長さだけ。** バーの幅、レールのマーカー位置、順位カードの並び替え。
3. **動きは 120〜180ms、イージングは減速系。** 連続操作(スライダードラッグ)中は**トランジションを 0 にする**(追従遅延はライブ更新の嘘になる)。
4. **注意を引く動きは1画面に1つまで。** 同時に複数箇所が光ると、どれが結論か分からなくなる。

### 8-2. 具体

| 出来事 | 動き | reduced-motion 時 |
|---|---|---|
| 最後のセルが埋まり結論が成立(§3-1⑤) | Z1 の縁が1回だけ明滅(1周期)+ Z3 の★が所定位置にフェードイン(150ms) | **明滅なし。★は即座に表示。**代わりに Z1 に `結論が出ました` を `aria-live` で流す(視覚以外の通知は両モード共通) |
| 順位の入替(Z2) | カードが左右にスライドして入れ替わる(160ms) | **スライドなし。即座に並び替わる** |
| Z3 の行の並べ替え | 行が上下に移動(180ms) | 即座に並び替わる |
| 貢献度バーの伸縮(Z4) | `width` のトランジション(120ms) | トランジションなし |
| レールの塗り分けの移動 | ドラッグ中は**トランジションなし**(1:1 追従)。`[閾値へ]` ボタン経由のときのみ 200ms で移動 | ボタン経由も即座 |
| θ 変更でラベルが変わる | Z1 のラベル部分がクロスフェード(120ms) | 即座に差し替え |
| 逆算警告の出現(Z5) | 上から高さが開く(150ms)。**明滅・振動はしない**(非難がましい演出を避ける。FR-18「警告であって禁止ではない」) | 即座に表示 |
| ソフト警告(7個目) | 同上 | 即座に表示 |
| 保存済み表示(Z0) | フェードイン → 2秒後フェードアウト | 表示 → 2秒後に消える(フェードなし) |
| rank invariance 文の点灯(§3-1④) | 1回だけ背景が明滅 | **明滅せず、常時表示のまま** |
| `[全消去]` の2段階変化 | ラベルの差し替えのみ(動きなし) | 同じ |

### 8-3. `prefers-reduced-motion` の扱い

- **`@media (prefers-reduced-motion: reduce)` で、上表の「動き」列を全て無効化する。** 情報は消さない — 動きが担っていた「注意の誘導」は、`aria-live` の通知と、静的な強調(縁・語)が引き継ぐ。
- reduced-motion 時に**代替として点滅や色の急変を入れない**(前庭障害への配慮は光刺激への配慮でもある)。
- **`transition` を使い、`animation` は原則使わない。** トランジションは `prefers-reduced-motion` で `transition-duration: 0.01ms` に落とすだけで無効化でき、状態の最終値が必ず正しく反映される。

### 8-4. 非モーションのフィードバック

| 出来事 | フィードバック |
|---|---|
| セルに値を入力 | ゴースト変換値が即時更新(§5-4)。総合スコアと順位が即時更新 |
| スライダー操作中 | つまみが「勝者ゾーン」のどちら側にいるかがレールの塗りで常時分かる(§4-1)。`aria-valuetext` が逐次読まれる |
| ★を越えた瞬間 | Z2 の1位が入れ替わり、Z1 の主語が変わる。**これ以上の演出を足さない** — 事実の変化自体が最も強いフィードバックである |
| フォーカス移動 | 可視のフォーカスリング(§6-2.3、形は identity 位相) |
| 保存 | Z0 の `保存済み`(§8-2) |
| エクスポート | Z0 の完了通知 + ブラウザ標準のダウンロード表示 |
