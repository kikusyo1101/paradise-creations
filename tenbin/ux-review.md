## 1. 総評

**一次出力の設計は正しく実装されている。しかし、二次出力の描画に致命的な脱落が1件あり、数値表示に仕様違反が1件ある。現状では出荷不可。**

良い点から言う。ux.md R1(「画面を開いて最初に読めるものは、順位ではなく頑健性の文章である」)は**実機で守られている**。DS-1 を描画すると、Z1 結論帯が `y=71.8` に始まり高さ 498.7px を占め、Z2 順位ストリップは `y=570.5` から始まる(実測)。順位が結論の上に来ることは構造的に起こり得ない。頑健性ラベルの左罫は robust=実線 / contingent=破線 / fragile=点線 が `border-left-style` の実測値で確認でき、FR-26④ の「色に加えて形と語」は満たされている。グレースケール化した画面でも点線罫と `fragile` の語で状態が読める。prd §5 の文言は、確認した範囲で**一字一句テンプレート通り**である。

しかし決定的な欠陥がある。**Z4「勝ち幅の内訳(勝敗貢献度)」のバーが1本も描画されていない**(欠陥 D-1)。DOM 上に4本の `.gbar` は生成され、`--gl` / `--gw` のパーセント値も正しく計算されて属性に載っているのに、`.axis0` と `.seg` が `<span>` のまま `display` を与えられておらず、実測サイズが **0×0px** になっている。画面には数値ラベル(`+300.0%` 等)だけが並び、`100% = 勝ち幅の全部` の基準線ラベルは軸のない空中に浮いている。ux.md §4-5 が「AC-12 の恒等式の可視化」と呼んだ中心装置、identity.md §5-7 が「貢献度バーもまた天秤になる」と設計した支点、その両方が画面上に存在しない。同じ原因で「各選択肢のスコアの内訳」の 100% 積み上げ帯も 12 区画すべてが 0 幅である。

もう1つ。**Z6 のゴースト変換値が仕様の10倍で表示されている**(欠陥 D-2)。AC-14 は「価格の生値 A=7 に対し、cost 反転後の表示スコアは **3.0**」と明記しているのに、画面には `変換後 30.0` と出る。ux.md §5-4 はこのゴースト値を「『低いほど良い、が効いていること』をユーザーが自分の目で検算できる唯一の場所」と位置づけている。その唯一の場所が、AC が定めた検算値と一致しない。

この2件はいずれも表層の描画・整形の問題であり、計算コア自体は正しい(Z1/Z2/Z3 の全数値が AC-01/05/06/07/08/11/13 の期待値と一致している)。修復は局所的で済むが、修復前に出荷してはならない。

## 3. 欠陥一覧

### D-1 【重大】勝敗貢献度バー・スコア貢献度帯が1本も描画されない

**現象**
Z4 の4本の勝敗貢献度バーと、3本のスコア貢献度 100% 積み上げ帯(計12区画)が、画面上に**まったく存在しない**。数値ラベルだけが並ぶ。

**根拠(実測)**
DS-1 / 1440px で `getBoundingClientRect()` を実測した結果:

| 要素 | 実測 box `[x, y, w, h]` |
|---|---|
| `.gbar`(行、価格) | `[798.5, 1060.8, 463, 22.8]` ← 行そのものは存在する |
| `.gbar .axis0`(軸) | `[798.5, 1083.5, **0**, **0**]` |
| `.gbar .seg`(バー本体) | `[798.5, 1083.5, **0**, **0**]` |
| `#stacks .bar > i` × 12 | 全て幅 0(bar 自体は `463×20`) |

4本すべての `.seg` が 0×0。`.seg` の `background` は正しく解決されており(価格=`rgb(231,116,107)`、負のバー=`repeating-linear-gradient(135deg, rgb(150,150,150) 0 3px, rgb(36,36,36) 3px 6px)`)、`--gl: 50; --gw: 50`(価格)等のカスタムプロパティも正しい値が載っている。**計算も色も正しいのに、箱が潰れているだけ**である。

**原因**
`index.html` L743 のテンプレートで軸とバーが `<span>`(inline)である:
```html
<span class="axis0"><i class="seg"></i></span>
```
CSS L443 `.gbar .axis0 { position: relative; height: 12px; ... }` は `display` を指定していない。inline 要素に `height` は効かず、`<i class="seg">` も inline のため `top/bottom/left/width` の絶対配置が成立しない。

**裏付け(修復の実証)**
検証用コピーに `.gbar .axis0{display:block} .gbar .seg{display:block}` の2行だけを追加して再撮影したところ、**4本のバーがすべて出現し、負の2本には斜線ハッチが乗り、100% 基準線が正しい位置に立った**。
→ `ux-review-shots/02-ds1-contribbars-displayblock-proof.png` と `01-ds1-desktop-1440.png` を並べれば差は一目で分かる。

**違反する仕様**
- FR-13(勝敗貢献度の表示)/ AC-11(価格 +300.0%)/ AC-12(100% 恒等式)/ AC-13(スコア貢献度)
- ux.md §4-5「`100%` 基準線は装飾ではなく、AC-12 の恒等式の可視化である」— その可視化が存在しない
- identity.md §5-7「中央軸が `--primary` になることで、貢献度バーもまた『支点のある横棒』= 天秤になる」— 支点も横棒も描かれていない
- `.gbar .axis0::before`(中央0軸、`--muted-soft` の1px)も同時に消えているため、**双方向バーの0点が画面上に存在しない**。ux.md §4-5 が要求した「軸は中心0の双方向」が成立していない

**修復提案**
```css
.gbar .axis0 { display: block; position: relative; height: 12px; ... }
.gbar .seg   { display: block; position: absolute; ... }
.stack .bar > i { display: block; }  /* 積み上げ帯側も同様に確認 */
```
`.stack .bar` は `display:flex` なので子 `<i>` はブロック化されるはずだが、実測で全区画が幅0のため、`flex-basis` / `width: calc(var(--p) * 1%)` の指定経路を併せて確認すること。修復後は必ず再描画して、価格のバーが 100% 基準線(`x=1107.2` に実在、`rgb(143,143,143)`)を越えることを目視すること — それが AC-12 の可視化である。

### D-2 【重大】Z6 のゴースト変換値が AC-14 の10倍で表示される

**現象**
採点グリッドの各セル下のゴースト値が、AC-14 が定めた 0-10 尺度ではなく 0-100 尺度で出ている。

**根拠(実測 — 画面テキスト全文より)**
| セル | 生値 | 画面表示 | **AC-14 の期待値** |
|---|---|---|---|
| ベンダーA × 価格(cost) | 7 | `変換後 30.0` | **3.0** |
| ベンダーB × 価格(cost) | 4 | `変換後 60.0` | **6.0** |
| ベンダーC × 価格(cost) | 6 | `変換後 40.0` | **4.0** |
| ベンダーA × 移行コスト(cost) | 2 | `変換後 80.0` | **8.0** |
| ベンダーB × 移行コスト(cost) | 6 | `変換後 40.0` | **4.0** |
| ベンダーC × 移行コスト(cost) | 8 | `変換後 20.0` | **2.0** |

12セルすべてで10倍。狭幅 375px でも同一(`変換後 30.0`、iframe 実測で `.ghost` の textContent を直接取得)。

**原因**
`index.html` L2388:
```js
setText(td.querySelector(".ghost"), (nv === null) ? "未入力" : "変換後 " + TenbinCore.fmt.score(nv));
```
`normalize()`(L902-909)は 0-1 の正規化値を返す(cost なら `(10-v)/10`、A×価格 = `0.3`)。一方 `fmt.score`(L783)は `(s * 100).toFixed(1)` — **総合スコアを 0-100 で表示するための整形関数**である。0-1 の素点にこれを掛けたため `30.0` になった。ここで必要なのは ×10。

**違反する仕様**
- **AC-14** の明文:「価格の生値 A=7 / B=4 / C=6 に対し、cost 反転後の正規化スコア(0-10 表示)は A=3.0 / B=6.0 / C=4.0」
- ux.md §5-4:「このゴースト表示は AC-14 のセル単位検証値そのものであり、**『低いほど良い、が効いていること』をユーザーが自分の目で検算できる唯一の場所**である」
- 加えて **尺度の不整合**という UX 上の実害がある。入力欄は 0-10 で受け付けるのに、その真下のゴーストは 0-100 で返る。ユーザーは「7 と打ったら 30 になった」という無根拠な変換を見せられ、cost 反転の理解を助けるどころか妨げる。ux.md §5-6 の足切り UI も「変換後スコアの 0〜10 尺度」と明記しており、アプリ内で尺度が二重化している。

**修復提案**
ゴースト専用の 0-10 整形を使う:
```js
setText(td.querySelector(".ghost"),
  (nv === null) ? "未入力" : "変換後 " + (nv * 10).toFixed(1));
```
`fmt.score` は総合スコア(0-100)用として温存すること。修復後、DS-1 の12セルが AC-14 の表(A=3.0/6.0…、8.0/4.0/2.0)と一致することを画面テキストで照合すること。

### D-3 【中】無効化された「逆転不能」ボタンのコントラストが AA 未達

**現象**
Z3 の逆転不能行(DS-1 のサポート行、robust の全3行)にある `disabled` ボタン「逆転不能」の文字色コントラストが 4.5:1 を満たさない。

**根拠(実測 — WCAG 2.x 相対輝度式で計算)**
| 前景 | 背景 | フォント | 実測比 | 要求 | 判定 |
|---|---|---|---|---|---|
| `rgb(102,102,102)` = `--muted #666666` | `rgb(24,24,24)` = `--canvas` | 13px / 400 | **3.09:1** | 4.5:1 | **FAIL** |

DS-1 画面の**全テキスト配色 22 組を実測した中で、これが唯一の FAIL** である(他 21 組は全て PASS、最小 4.79:1)。

**違反する仕様**
identity.md §2-3 は `--muted` を「非活性・プレースホルダ。**本文には使わない**(3.09:1)」と定義しており、非活性ラベル用途としては §2-4 で「非活性ラベルのみ PASS」と自ら許容している。したがって identity.md の文面上は違反ではない。**しかしこのボタンが伝える「逆転不能」は、この製品で最も重要な意味の1つ**(FR-09 / AC-07 / AC-17)であり、robust ケースでは**全行がこの表示になる**。「読めなくてよい非活性ラベル」ではなく「読ませなければならない状態表示」である。

**修復提案**
disabled ボタンの色を `--muted-soft #8f8f8f`(canvas 上 5.49:1、実測 PASS)に上げる。無効であることは `disabled` 属性・カーソル・枠線が既に伝えており、色を落として伝える必要はない。なお、同じ意味は隣接する `—(逆転不能)` と本文の理由文(いずれも AA PASS)でも冗長に伝えられているため、実害は限定的で【重大】には数えない。

### D-4 【軽微】重みスライダーの `aria-describedby` が空文字で上書きされている

**現象**
`index.html` L2060 で、描画のたびに全レールの `aria-describedby` が空文字に設定される:
```js
rail.setAttribute("aria-describedby", "");
```
実測でも4本すべての `aria-describedby` が `""`。

**根拠**
ux.md §6-3 は重みスライダーに「`aria-label` + `aria-describedby`」を求め、`逆転する重みは {w_k*} パーセント` を読ませると定めている。現状その情報は補助技術に届かない。

**緩和事情**
`aria-label`(`移行コストの重み`)と `aria-valuetext`(`15.0パーセント`)は正しく設定されており、ux.md §6-3 が「生の 35 が『35』とだけ読まれるのを防ぐ」ために要求した `aria-valuetext` は満たされている。逆転閾値の情報も、同じ行の `[21.8% へ]` ボタンのラベルと本文テキストで読める(ux.md §4-4 経路B が「AC-10 のキーボード経路」と定めた受け皿は機能している)。したがって情報の欠落ではなく、冗長性の欠落である。

**修復提案**
空文字を代入するくらいなら属性ごと削除する(`removeAttribute`)。空の `aria-describedby` は一部の支援技術で不正な参照として扱われうる。閾値の予告文を読ませたいなら、行内の `.crit-line` に id を振って参照する。

### D-5 【軽微】狭幅で `<thead>` が `left:-9999px` に飛ばされる

**現象**
`@media (max-width: 720px)` の `#grid thead { position: absolute; left: -9999px; }`(L529 付近)により、375px 幅では列ヘッダが画面外 `x=-9999` に置かれる。iframe 実測でオフスクリーン要素 16 件を検出したが、**その全てがこの `thead` 配下**(と `.skip` リンク)であり、意図されたものである。

**評価**
これは**欠陥ではなく正しい実装**と判定する。各 `<td>` には `data-label`(`価格` / `機能充足度` / …)が 12/12 セル全てに付与され、`::before { content: attr(data-label) }` で各行に基準名が表示される(実測: `content: "価格"`)。`<th scope="row">` の意味論も保たれている(ux.md §1-3 の要求)。**横スクロールも発生していない**(375px viewport で `documentElement.scrollWidth = 360` < `clientWidth = 360`、iframe による厳密実測)。

**唯一の指摘**は、`left:-9999px` 方式は画面外に置くだけでフォーカス順には残るため、キーボードで `thead` 内の要素に到達すると視覚的に何も見えない位置にフォーカスが飛ぶこと。ただし現行 `thead` にフォーカス可能要素は存在しないため、実害はない。将来ヘッダにボタンを足す際は `.sr-only` パターン(clip-path)に切り替えること。

## 6. 良いと認める点

1. **R1(結論が順位より先)が構造として担保されている。** Z1 が 498.7px、Z2 がその下。sticky でも縦順序は不変。「順位を先に見せたい」という誘惑に一度も負けていない。

2. **3状態の識別が色に依存していない。** solid / dashed / dotted の左罫は、identity.md §2-4 が警告した「fragile と contingent の相互コントラスト 1.00:1」という危険に対する、正面からの回答である。グレースケール画像で実際に判別できることを確認した。実線→破線→点線が「連続性が失われていく」という意味論に対応している点も美しい。

3. **prd §5 の文言が改変されていない。** DS-1 の理由文は AC-08 の期待値と一字一句一致する。空状態3種(`まず、比べたいものを2つ以上足してください。` / `比べる相手がいません。選択肢をもう1つ足してください。` / `何で比べるかを決めてください。基準を1つ以上足してください。`)も正典通り。「言い換えたくなる」誘惑に負けていない。

4. **境界状態が丁寧に作られている。** 選択肢1件では Z2/Z4 が `hidden` になり、Z3 は残るが `[閾値へ]` が `disabled` + `結論が出ていないため、逆転閾値は計算できません。` に切り替わる。ux.md §7-1 の表の通り。**「Z3 を重み設定パネルとしてのみ機能させる」という設計判断が、実機で正確に再現されている。**

5. **robust の扱いが誠実である。** 3行すべてが「逆転不能」になり、★が画面上に1つも存在しない。但し書き `基準そのものが抜けている可能性は、この分析では検出できません。` が結論帯の中にある。祝福の演出は一切ない。ux.md §2-3(b)「robust の帯を『祝福』として演出しない」が守られている。

6. **Z3 の統合判断が機能している。** 「基準パネル」と「臨界度ランキング」を1つに畳んだ ux.md §1-1 の最大の構造判断は、実機で正しく動く。DS-1 では **重み最小の移行コスト(15.0%)が1番上、重み最大の価格(35.0%)が2番目**に来る — AC-06 の反直感的洞察が、行の並び順そのものとして目に見える。各行に `現在 15.0% → 逆転 21.8%(+6.8ポイント)` と符号付きで数値が併記され、`ここまで ベンダーB が1位` / `ここから ベンダーA が1位` の文字ラベルが帯の意味を色に頼らせていない(R2 遵守)。

7. **`outline: none` が0件。** アクセシビリティで最も安易に壊される場所が、壊されていない。実測で 2px solid white / offset 2px のリングを確認した。

8. **合計表示の但し書きが正しい。** `合計 100%(内部では常に厳密に 100%)` — AC-04 の丸め誤差(表示合計が 100.1% になりうる)を、ユーザーに不具合と誤認させないための一文が、ux.md §5-3 の指示通りに実装されている。細部への誠実さが表れている。
